## 생성 및 수동 편집 계약

- 자동 관리: `Assets/Art/Generated`, 장면의 `GeneratedVillage`, 생성 스크립트에서 관리하는 렌더·플레이어 설정.
- 수동 관리: 장면의 `ManualEdits`와 그 밖의 사용자 루트, `Assets/Art/Manual` 등 Generated 밖의 자산.
- 사용자가 외형을 수정하려면 원본을 별도 .blend로 복사하고 FBX를 Generated 밖에 출력한다. 생성 Prefab 자체를 고치면 재생성 때 교체된다.
- 재생성은 기존 장면을 열고 GeneratedVillage만 교체하며 자산 경로·GUID를 유지한다. 수동 자산은 Generated 자산의 이름 변경·삭제에 의존하지 않게 관리한다.
- 저장 시스템과 영구 주민 ID는 이후 구현한다. 현재 Resident_01~06은 장면 이름이며 저장 형식으로 확정하지 않는다.

## 이동 보완 결정

- 기존 부지런함·느긋함은 유지하고 길 선호도만 고정 시드로 추가한다. 성향은 안전한 선택 사이의 선호에만 영향을 준다.
- 장애물에는 정지에 필요한 거리까지 검사해 벽 앞 급정지를 줄인다. 막힌 선호 방향은 고집하지 않고 안전한 출구를 찾아 제자리 회전한다.
- 이동 대기에는 걷기 피로를 부과하지 않고, 감상도 작업 피로를 부과하지 않는다. 운반 중 실제 이동에는 운반 피로를 적용한다.
- ActivitySlot은 Unity 직렬화 안정성을 위해 동일 이름의 별도 파일로 분리했다.
- 검사 결과는 보정 함수의 자체 거리값이 아닌 실제 위치와 이동 구간에서 측정한다. 이전 고정 경로 검사 통과 기록은 사물 관통 방지의 증거로 사용하지 않는다.

| 결정 | 이유 | 적용 범위 / 확인 |
|---|---|---|
| 첫 자원은 당근과 식량 | 생산 흐름을 작게 검증 | 목재·화폐·확장은 5단계 이후 |
| 식량 시작/최대 12/24, 수확당 3 | 짧은 관찰에서 생산과 소비를 모두 확인 | VillageResources 기본값 |

| 생산·균형·여유 3단계 | 주민 직접 명령 없이 마을 방향을 제시 | HUD와 VillagePriority |
| HUD는 기본 표시, F 진단과 분리 | 일상 화면을 간결하게 유지 | Tab으로 HUD 숨김 |

## 6단계 결정

- Esc 메뉴는 IMGUI MouseDown 누락에 의존하지 않도록 런타임 Input을 Update에서 한 번 처리한다. 버튼은 같은 영역에서 누르고 뗄 때 실행하며, 영역 밖 해제와 포커스 상실은 취소한다. 화면과 입력은 동일한 메뉴 좌표를 사용한다. Unity 버전은 유지한다.

| 결정 | 이유 | 적용 범위 / 확인 |
|---|---|---|
| 로컬 JSON 저장 형식 버전 1과 주 파일·백업 파일 사용 | 저장 중 중단 또는 형식 변경에 대비하고 외부 서비스 없이 이식성 유지 | `Application.persistentDataPath`, `tiny-days-save.json` 및 `.bak` |
| 주민 ID·밭 ID·행동 자리 ID로 진행 행동 복원 | 위치만 되돌린 뒤 행동을 다시 뽑지 않고 저장 시점의 이동·운반·건설을 이어감 | 예약 복원 불가 시 해당 주민만 안전하게 유휴 상태로 전환 |
| Esc 설정 메뉴에서 저장·불러오기·음량 제공 | 플레이 화면을 과하게 늘리지 않고 사용자 설정의 진입점을 제공 | 메뉴를 열면 일시정지하고 닫을 때 이전 일시정지 상태를 복원 |
