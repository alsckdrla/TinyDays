# Tiny Days Prototype 마스터 플랜

## 목표

Windows용 Unity + Blender 프로토타입. 플레이어는 마을의 큰 방향만 제시하고, 주민과 마을은 환경과 필요에 맞춰 스스로 생활·생산·발전한다. 화면 한쪽에 오래 켜두고 가끔 바라보고 싶은 따뜻한 미니어처 농촌 디오라마를 만든다.

## 핵심 원칙

- 기능 수보다 화면 품질, 읽기 쉬운 실루엣, 안정적인 자율 생활을 우선한다.
- 주민 판단, 이동, 작업 예약, 자원, 화면 표현, 저장을 분리한다.
- Unity 2022.3.20f1과 Blender 5.2.1을 유지하고 외부 유료 에셋·외부 서비스는 사용하지 않는다.
- 생성 영역은 `Assets/Art/Generated`와 장면의 `GeneratedVillage`로 한정하며, `ManualEdits`와 수동 자산을 보존한다.
- 모든 반복 생성은 원본 `.blend`, 생성 스크립트, Unity 소스를 남기고 중복 배치를 만들지 않는다.

## 프로토타입 범위

- 고정 농촌 지형 1곳, 주민 6명, 집 2채, 공동 창고 1채, 밭 2구역, 작물·식량 각 1종.
- 카메라 이동·확대·기본 구도, 낮·일몰·밤·새벽, 일시정지·1×~16× 배속·HUD 숨김.
- 주민의 걷기·농사·운반·건설·휴식·감상, 생산/균형/여유 방향 제시.
- 저장공간 부족에 따른 저장 헛간 확장 1회.
- 6단계에서 Windows 실행 파일, 설정과 마을 상태 저장·복원, 장시간 안정성 검증을 추가한다.

제외: 랜덤 지형, 사계절·복잡한 날씨, 관계·출산·노화, 교역·여러 마을·멀티플레이·모바일·Steam 연동.

## 시각 기준

- 비스듬히 내려다보는 직교 미니어처 구도, 단순한 입체 형태와 읽기 쉬운 실루엣.
- 따뜻한 햇빛·부드러운 그림자, 초록·노랑·흙색 중심의 색감, 충분한 여백.
- 집·창고·울타리·밭·식물·생활 소품과 서로 다른 행동의 주민으로 생활감을 만든다.
- 큰 UI·숫자, 현대 공장·아스팔트, 강한 화면 흐림은 사용하지 않는다.
- 참고 이미지는 `Docs/References/TinyDays_VisualTarget.png`를 기준으로 하며, 토끼 주민은 교체 가능한 임시 샘플이다.

## 구현 책임

- 시간: 하루 흐름, 일시정지, 1×~16× 배속.
- 주민 판단: 시간·피로·작업 필요·방향에 따른 다음 행동 선택.
- 작업 관리와 이동: 행동 자리 예약, 목적지 이동, 경로 실패 복구.
- 마을 상태: 작물·식량·저장공간·확장 상태.
- 화면 표현: Blender 모델, 절차적 움직임, 조명, 소리.
- 저장: 안정 식별자와 저장 형식 버전을 가진 마을 상태·사용자 설정.

## 단계별 로드맵과 통과 기준

### 1단계 — 정지 화면과 아트 기준

**상태: 구현·자동 검증 완료, 사용자 시각 확인 대기.** 고정 지형, 집 2채·창고 1채·밭 2구역, 흙길·울타리·식물·생활 소품, 교체 가능한 주민 샘플, 직교 카메라와 일몰/낮/밤 조명을 구현한다. Unity 장면·Play Mode·콘솔 오류, 960×540·1280×720 구도, 대표 캡처에서 집·밭·길·주민의 가독성을 확인한다.

### 2단계 — 움직이는 풍경

**상태: 구현·자동 검증 완료, 사용자 5분 관찰 대기.** 주민 6명의 이동·걷기·방향 전환, 작물 흔들림, 굴뚝 연기, 연속 낮밤 변화, 환경음과 음량 구조를 구현한다. 5분 관찰에서 이동 밀도·발 미끄러짐·동시 행동·조명 튐이 없는지 확인한다.

### 3단계 — 자율 생활

**상태: 구현·자동 검증 완료, 사용자 15분 관찰 대기.** 작업·운반·휴식·감상, 피로·시간대·개인차 기반 선택, 행동 자리 예약, 접근 실패 시 다른 행동 선택, 숨길 수 있는 진단 화면을 구현한다. 15분 무입력 중 행동 순환·휴식 뒤 복귀·주민 겹침 방지·영구 정지 부재를 확인한다.

### 4단계 — 생산과 방향 제시

**상태: 구현·자동 검증 완료, 사용자 시각 확인 대기.** 작물 관리→성장→수확→운반→저장→식량 소비를 연결하고, 생산/균형/여유 방향, HUD 숨김, 일시정지와 1×~16× 배속을 제공한다. 방향 변화가 행동 비중에 반영되고, 부족 상황에서도 생산·휴식 순환이 회복되는지 확인한다.

### 5단계 — 작은 자율 발전

**상태: 구현·자동 검증 완료, 사용자 시각 확인 대기.** 저장할 수확 상자가 있는 저장공간 부족이 30초 지속되면 후보지에 작은 목조 헛간을 한 번 결정한다. 주민의 실제 건설 60초 누적으로 기초·골조·완성 외형을 전환하고 용량을 24에서 36으로 늘린다. 저장공간이 충분하거나 부족이 잠깐이면 확장하지 않고, 완공 뒤에는 중복 확장을 막는다.

### 6단계 — 실행·저장·안정성

**상태: 진행 중.** Windows x64 실행 파일과 16배속 성능 진단, 버전 1 로컬 저장/복원을 구현했다. 저장은 주민의 위치·현재 행동·예약·운반 상태, 작물, 식량, 확장 진행, 시간·HUD·카메라·음량 설정을 복원하며 주 파일과 백업 파일을 안전하게 교체한다. 숨김 창 16× 5분 측정은 목표를 통과하지 못했으므로 추가 최적화는 보류한다. 남은 범위는 작은 창 대응과 30분·2시간 안정성 검증이다.

## 작업 규칙

6단계 저장 메뉴는 Update의 마우스 입력과 읽기 전용 화면 표시를 분리하며, 메뉴 내 완료 안내를 유지한다. 기존 별도 EditorWindow 검사는 실제 Game 창 입력의 통과 근거로 사용하지 않는다. 실제 검증 결과는 Progress.md와 SaveMenuVerification.txt를 따른다.

- 매 작업 전 이 문서의 단계별 로드맵을 기준으로 범위·통과 기준·확인 대기 항목을 확인하고, 이어 `Docs/Progress.md`, `Docs/Decisions.md`를 읽는다.
- 현재 단계의 오류와 사용자 확인을 우선하며, 단계 범위를 넘는 기능은 사용자와 합의한 뒤 진행한다.
- 작업 뒤 실제 구현·검증 결과와 미검증 사항을 `Docs/Progress.md`에 기록한다.
- 이 문서는 Git 추적 대상이다. 향후 원격 저장소에 변경 사항을 올릴 때 반드시 함께 커밋·푸시한다.
