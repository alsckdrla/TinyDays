### Esc 메뉴 입력 보완 — 2026-09-14

- 사용자에게 저장/불러오기 무반응 보고를 받았다. 종전 검사는 함수를 직접 호출했으며 실제 버튼 입력을 검증하지 않았다. 사용자 환경의 무반응 원인 자체는 확정하지 않았다.
- 설정 메뉴를 독립 모달 창으로 바꾸고 열린 동안 HUD·진단 패널의 입력 겹침을 차단했다. 버튼 실행은 다음 Update에서 처리하며 결과 문구를 메뉴 안에도 유지한다.

## 6단계 선행: 16배속 관찰 개선

- 주민 이동의 컴포넌트 검색·배열 생성·참조 갱신을 캐시로 교체하고, 같은 렌더 프레임의 주민 메시 애니메이션 갱신을 한 번으로 제한했다. 이동·충돌의 0.05초 안전 시뮬레이션 간격은 유지한다.
- `PerformanceMonitor`와 Windows x64 빌드 스크립트를 추가했다. 16×에서 Unity 시간 제한을 30fps 목표에 맞춰 조정해 시간 손실을 줄인다.
- Windows 1280×720 숨김 창 5분 측정 결과는 평균 54.2fps, P95 118.8ms, 게임 진행 14.7×였다. 목표(평균 30fps, P95 50ms, 16× ±5%)를 통과하지 못했다. 숨김 창의 OS 렌더링 제한이 포함될 수 있으므로 실제 보이는 창에서 재측정이 필요하다.
- 변경 뒤 Unity Play Mode 900초 생활·이동·생산·확장 자동 검증은 통과했다.

- 생성 자산/장면 영역과 ManualEdits 분리, 재생성 자동화 및 로컬 Git 관리.

- 자동 검증 결과: `Docs/Verification.txt`. 원시 실행 로그는 `Logs/`에 보관하며 로컬 Git에서는 제외.

## 발견·수정한 문제

1. 사용자 Blender 애드온들이 백그라운드 실행 시 오류 발생 → 기본 설정 실행으로 분리. 사용자 설정 변경 없음. 최종 생성 로그에는 해당 오류 없음.
2. FBX 루트 단위/축 변환을 배치가 덮어써 모델이 작아짐 → 원본 변환을 Visual 자식에 유지하고 독립 부모로 배치. 실제 월드 크기 회귀 검사 추가.
3. 지붕 면이 안쪽을 향해 지붕이 비어 보임 → 면 순서 수정, 캡처로 확인.
4. 뒤쪽 건물 입구가 반대로 보임 → 입구가 흙길을 향하도록 회전, 옆면 창 추가.
5. 검증용 오브젝트 제거가 저장되지 않음 → 장면 변경 명시 후 저장, 재검증 통과.
6. 분리 토끼의 일부 렌더러와 입자 렌더러가 재질 검사에 섞임 → 주민 전체 Bounds와 MeshRenderer만 검사하도록 조정.
7. 연기 입자가 사각형으로 보임 → 로우폴리 돌 메시를 입자로 사용하고 미리 채워 정지 화면에서도 읽히게 조정.

## 검증하지 않은 부분과 한계

- 실제 키보드·마우스를 물리적으로 입력한 검사는 하지 않았다. 기본 InputManager의 WASD·방향키 매핑 및 런타임 메서드를 확인했다.
- 6장은 Unity 카메라 렌더 캡처이며 실제 데스크톱 창 스크린샷은 아니다.
- Windows 독립 실행 파일, 프레임 속도, 장시간 안정성, 저장·불러오기는 6단계 대상이며 이번에 구현·측정하지 않았다.
- 모델은 교체 가능한 초기 샘플이다. 참고 이미지보다 지형과 길이 규칙적이고, 소품 밀도·재질·접지 음영이 단순하다. 현대 시설·큰 UI·강한 흐림은 의도적으로 제외했다.
- 밤은 주민과 시설을 구분할 수 있도록 주변광을 남겼다. 사용자 화면에서 더 밝거나 어둡게 조정할 수 있다.
- 이번 검증은 900초 가속 시뮬레이션과 별도 일반 Editor Play Mode 30초 관찰이다. 실제 15분 연속 화면 관찰과 키·마우스 물리 입력은 미검증이다.
