# 생활 경로 계산 성능 v0.138

2026-10-04. 물뿌리개를 내려놓은 뒤 벤치로 이동하는 계획 계산을 최적화한다. 생활AI나 새 경로 후보/동작은 추가하지 않는다.

## 변경과 보존

- 메시 정점·가중치·바인드 배열을 계획 한 번 안에서 보관해 피부 검사마다 다시 복사하지 않는다. 기존 네 가중치의 계산 순서는 유지한다. 전역 캐시가 아니므로 새 계획/모델/장애물 변경 시 새 자료를 읽는다.
- 정확히 같은 시작/끝 준비 자세의 검사를 계획 안에서 재사용한다. 캐시 키의 좌표·회전은 반올림하지 않는다.
- 장애물 삼각형의 실제 경계를 공간 셀에 등록하고 검사AABB 전체와 겹치는 셀만 조회한다. 같은 삼각형은 한 조회에서 한 번만 비교한다. 기존 삼각형/SAT/피부 정점의 실제 판정은 그대로 수행한다.
- 장애물 여유5cm·240Hz 준비 자세/60Hz 피부 표본·발 고정3.5mm/접지5mm/침범0.5mm·도달 기준을 완화하지 않았다. 화단·집·문·벤치·보관 소품과 막힘 대기/재개를 유지한다. 모델/원본 클립·생활 흐름·카메라 변경 없음.

## 측정과 검사

수정 전33배치 기준은 `RabbitRoute138Before.txt`, 전후 시간/경로 비교는 `RabbitRoute138Comparison.txt`에 보존한다. `RabbitRoutePerformanceChecks.Finish`의 초기 측정은 기본 경로1324.366→350.068ms였다.33개 모두 성공/막힘·준비 위치/방향·길이·9개 경로 표본이 소수6자리에서 같았다. 이는 편집기의 직접 함수 검사이며 모든 곡선 시점의 수학적 동일성을 주장하지 않는다.

이번 수정 전 실행 파일은1408ms였고, 이전 v0.135의2544ms 측정과 조건이 달라 감소율을 혼용하지 않는다. 기존 경로 품질과 새로운 성능 확인은 별개다. 초기 자료 재사용만으로는 시간 감소가 작아 공간 조회를 추가했다. 첫 장기 검사 실행은 추가 최적화를 위해 해당 전용 배치 프로세스만 중단했고 최종판으로 다시 수행한다.

회피32배치·한쪽/양쪽 차단·해제 후 재개·5개 중단 위치와240/30/60/120fps×두 배속의 기본 회귀는 통과했다.19완료/13안전 대기를 유지한다. 물 주기·벤치·전체 흐름·실내/실외20회씩 반복도 통과했고 주민/소품 누적 변동0이었다. 출입/자동문·걷기/달리기96정지 조합, 원본/FBX·저장 장면 해시 보존과 Windows 빌드도 통과했다. 최종 로그 `Logs/route138-final2.log`의 `ROUTE138_COMPLETE_OK`와 종료 코드0을 확인했다.

편집기33배치 평균1138.192→310.154ms, 최대2107.279→549.490ms였다. 실제 실행 파일 자동 전체 흐름도 완료(`Logs/route138-player-after.log`, `WATER_BENCH_LIFE_PLAYER_OK`), 수정 전1408ms→수정 후493ms로 약65% 단축했다.자료 구성87→69ms, 손잡이 오차0.293mm·고정발 이동0.396mm·최저 신발 높이2.018mm였다. 약0.5초 계산이 남아 무지연을 보장하지 않는다. 직접 OS 입력·사용자 동작 품질은 별도 확인 대기다.

## 실행과 다음 확인

생활 실행 파일은 `Logs/RabbitHomeLifePlayer/TinyDaysRabbitHomeLife.exe`다. `-waterBenchLifeSmoke` 자동 실행은 실제 프로그램에서 함수 콜백을 실행하며 OS 버튼 입력을 대신하지 않는다. **경로 계산 지연 감소 사용자 확인 대기**. 사용자에게는 내려놓기 후 출발 지연과 전체 생활 흐름을 확인받는다. 자세 품질의 기존 미승인을 성능 개선으로 승인 처리하지 않는다. 다른PC에서도 `RabbitRoutePerformanceChecks.Finish`는 Docs의 보존 기준을 읽어 검증한다.
