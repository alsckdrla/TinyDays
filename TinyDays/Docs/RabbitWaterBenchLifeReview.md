## 동작과 조작

- `RabbitHomeLifeStudy`/Windows 생활 검토의 **생활 흐름 · 외출해서 물 주기** 모드에서 **전체 생활 · 물 주기 후 벤치 휴식**을 누른다. 기존 물 주기까지만 재생하는 버튼과 개별 벤치 모드는 유지한다.
- 실내 대기 → 자동문 외출·닫힘 대기 → 집기·운반·물 주기 → 보관점 복귀·내려놓기 → 벤치 접근 → 최대3걸음 방향 정리·낮은 두 걸음 착석 준비 → 앉기 →6초 휴식 → 일어서기 → 약1m 이동·서서 대기. 최초 약45.75초,0.5배에서는 약91.5초다.
- 접근은 문 앞쪽의 기존 안전한 공간에서 보관 접근점과 벤치 접근점을 연결한다. 주민을 개별 벤치 시작점으로 옮기지 않는다. 현재 위치/방향과 자세를 인계하며 한 제어만 몸을 움직인다. 물뿌리개는 원위치·방향과 표시를 유지한다.
- 기본 호흡과 눈 깜빡임 시간은 단계 변경으로 초기화하지 않는다. 벤치 연결에서는 진행 중인 호흡 위상에0.25초 혼합으로 합류한다. 기존 개별 검토의 초기화/포즈 선택 규칙은 유지한다.
- 진행 중 반복 재생 요청은 무시한다. 정지는 걸을 때 감속하고 착석/기립은 안전한 끝까지 마친다. 앉는 중/휴식 중 정지하면 앉은 호흡을 유지하며 자동 기립을 취소한다. 재생은 중단 단계부터 이어간다. 완료 후 다시 재생하면 실외에서 물 주기부터 시작하며 자동 귀가하지 않는다.
- 초기화는 실내·문 닫힘·소품 원위치·물 효과 꺼짐이다. 모드 변경은 기존 검토 초기화와 소유권 정리를 따르되 얼굴 시계는 보존한다. 배속/일시정지/카메라/왼쪽 스크롤을 유지하며 전체 측면/비스듬/정면 구도를 추가했다.

## 검증과 남은 확인

- 첫 초안에서 프레임 전후의 팔 이동을 제어 인계 위치 튐으로 잘못 분류했다. 인계 함수의 직전/직후 실제 뼈 위치 차이를 별도 검사하며, 프레임 이동량은 정상 걷기를 포함한 값으로 구분한다. 보행 중단 후 접근 방향이 이미 맞을 때 긴 뒤걸음을 시작할 수 있는 분기도 바로 접근 보행으로 수정했다.
- 실물 소품 검사를 추가하자 내려놓기 직후의 회전에서 신발이 물뿌리개 몸통과 겹치는 것을 발견했다. 연결용 접근 거리를 소품의 보관 방향 메시/회전 신발/7cm 여유에서 계산하고, 필요한 경우 낮은 발 정리 한 쌍으로 떨어진 뒤 회전한다. 더 먼 접근에서의 손 도달은 두 작업 전환의 굽힘 진행도에 따른 작은 골반 전방 이동으로 맞췄다. 기존 물 주기 단독 접근과 작업 클립은 보존한다. 운반 중 방향/위치가 아니라 **보관 방향**으로 소품 경계를 계산해 반복 오차를 없앴다.
- 240Hz: 벤치 지지 신발 최저+2.447mm·지지 간격2.554mm·고정발 이동0.163mm·도달 초과0.001mm. 제어 인계 직전/직후 위치 차이0, 정상 걷기를 포함한30fps 루트 이동 최대38.334mm/프레임. 손잡이 접촉/도달·기존 접지 기준도 전 구간에서 통과했다. 실제 벤치 내부/지지 영역/공중 발5~6cm, 보관 소품 내부와 안전한 문 영역 검사를 유지했다. 정점·시간 표본 검사이며 모든 연속 충돌을 보장하는 물리 시스템은 아니다.
- 30/60/120fps×0.5/1배,12개 단계의 반복·정지·재개·일시정지·모드 정리·얼굴 시간 보존 통과. 실외20회+실내 초기화부터20회 및 추가 최종 위치 비교40회에서 주민 위치·방향/소품 위치 변동0을 확인했다. `RabbitWaterBenchLifeVerification.txt`/`RabbitWaterBenchLifeRepeat.txt` 참조. 초기2mm 도달 실패는 운반 중 경계 대신 보관 경계를 사용하도록 고친 뒤 해소했다.
- 기존 물 주기까지만 흐름, 출입240Hz·20왕복·걷기/달리기96정지 조합·물 주기/벤치 회귀 통과(`water-bench127-complete.log`). 최종 연결 검사/1373프레임×세 구도 렌더/Windows 빌드 성공(`water-bench127-final4.log`). 기본 원본·파생 Blender5개와 기존 동작/생활 FBX4개의 바이트 SHA 보존은 `RabbitWaterBenchLifePreservation.txt`다.
- 최종 영상은 `Flow0_1x.mp4`/`Flow45_1x.mp4`/`Flow90_1x.mp4`, 단계 대표39장은 같은 폴더다. 이전140/180도 초안 구도는 최종 비교 근거에서 제외한다. 첫 플레이어 카메라가 편집기 렌더와 반대로 집 뒤를 보던 것을 발견해 좌표를 맞추고 프로그램을 재빌드했다. 실제 입력 확인과 사용자 품질 승인은 별도다.
- 그래픽 플레이어 자동 실행은 새 전체 흐름/기존 물 주기까지만/출입/물 주기/벤치5종 모두 종료0이다. 카메라 수정 후 전체 흐름도 다시 종료0(`bench127-final-player.log`, `WATER_BENCH_LIFE_PLAYER_OK`), 실행 카메라와 세 구도 렌더 좌표 검사/빌드 성공(`water-bench127-camera-build.log`). `PlayerFinishedFinal.png`에서 원래 SkinnedMeshRenderer를 사용하는 실행 프로그램의 최종 서기·벤치·보관 소품을 시각 확인했다. 직접 OS 입력 검사가 아니라 자동 콜백/카메라 렌더다.
- 자동 검사·평가된 피부 포즈 렌더·실제 그래픽 플레이어 자동 콜백·직접 OS 입력·사용자 품질 승인은 각각 구분한다. 직접 마우스/키보드 입력과 사용자 자연스러움 승인은 아직 확인하지 않았다.
- 새 클립/Blender/FBX 재생성 없이 기존36개 몸동작·운반/집기/내려놓기·벤치 클립을 재사용한다. 기본 원본과 기존 아트 파일을 보존한다. 이전 동작의 최종 승인은 추정하지 않는다.
