# 2-2 토끼 외형 실제 화면 관찰

날짜: 2026-09-14. 사용자 외형 승인: **대기**.

## v0.11 사용자 스케치 기준 얼굴 재확인

- [사용자 스케치](References/RabbitFace_UserSketch_2026-09-14.png)를 보존하고 원본과 SHA-256 일치를 확인했다. 수정 전 결과는 [v0.10 Unity 비교표](Captures/Stage22/BeforeSketchFaceRevision/Unity-ReviewSheet.png)와 해당 폴더에 보존했다.
- 눈 전체 폭·높이·위치·간격을 유지하고, 흰자 안의 눈동자를 약 75% 크기의 둥근 곡선으로 구성했다. 작은 코 아래 수염 패드는 위가 좁고 아래가 둥근 두 갈래로 변경했다. 머리·귀·몸·복장·기본 자세와 색상은 유지했다.
- 두 자세의 정면·비스듬한 구도 및 축소 화면에서 눈동자와 흰자, 코와 패드의 연결을 확인했다. 완전 측면에서는 정면을 향한 눈동자가 좁게 보이며, 눈의 전체 깊이는 기존과 동일하다.
- 자동 생성·FBX 가져오기·재질·크기·접지·수동 영역 보존 검사 통과. 실제 Unity Game 창에서 새 얼굴과 두 자세의 표시를 확인했다. Play 버튼 입력 시 사용자 조작이 감지되어 입력이 실행되지 않았으며, 재관찰만 수행했다. 이번 수정 후 Play 모드 재진입은 미실시다.
- **2-2 사용자 재확인 대기**다. 시선·표정·자세 전환 애니메이션은 미제작이다.

## v0.10 흰자 추가 후 재확인

- 기존 검은 눈의 크기·간격을 유지하고 바깥 가장자리에 따뜻한 아이보리색 흰자를 소량 추가했다. 눈 전체를 둘러싸는 흰 테두리는 사용하지 않았다.
- Blender·FBX·Unity의 흰자 재질을 연결하고 경계가 매끈하게 보이도록 정리했다. 양쪽 기본 자세와 정면·측면·비스듬한 구도에서 확인했다. 측면에서는 정면보다 흰자가 더 많이 보인다.
- 최종 자동 생성·가져오기·재질·크기·접지·수동 영역 보존 검사 통과. 실제 Unity Game 창의 Play 모드에서 두 자세의 흰자 표시를 확인했다.
- 수정 전 이미지는 [v0.9 Unity 비교표](Captures/Stage22/BeforeScleraRevision/Unity-ReviewSheet.png)와 해당 폴더에 보존했다. **2-2 사용자 재확인 대기**이며 시선 이동 애니메이션은 아직 만들지 않았다.

## v0.9 얼굴·어깨·낮은 자세 보완 후 재확인

- 입 주변의 두 볼록한 부분을 줄이고 눈을 키워 간격을 좁혔다. 어깨·몸통·목을 이어진 표면으로 갱신하고 관절 영향을 다시 연결했다. 기존 색상과 18개 관절 이름·두 정지 자세를 유지했다.
- 네 발 자세는 몸을 낮추고 뒷다리를 접었다. 목과 머리를 앞으로 연결하고 꼬리를 엉덩이 뒤로 옮겼다. 정면·측면·후면·비스듬한 구도 및 축소 렌더에서 얼굴·어깨·접지·실루엣을 관찰했다. 심한 옷 관통이나 관절 틈은 보이지 않았으며 움직이는 동안의 변형 품질은 미검증이다.
- 최종 Blender와 Unity 재생성·크기·재질 검사 및 수동 영역 보존 검사가 통과했다. 최종 원본의 네 발 접지 높이는 앞발 약 -0.0094m·뒷발 약 0m로 기존 허용 오차 안에 있다. 검사 중 발견한 중간 생성물의 앞발 연결 오류는 최종 생성물에서 해소했다.
- 실제 Unity Game 창의 QHD 출력·0.86× 표시에서 Play 모드에 진입해 두 자세와 수정된 외형이 유지되는 것을 확인했다. 카메라 렌더 이미지와 실제 Game 창 관찰은 구분한다.
- 수정 전 v0.8 결과는 [Blender 비교표](Captures/Stage22/BeforeLowPoseRevision/Blender-ReviewSheet.png)·[Unity 비교표](Captures/Stage22/BeforeLowPoseRevision/Unity-ReviewSheet.png)와 같은 폴더의 개별 이미지로 보존했다.
- **2-2 사용자 재확인 대기**다. 2-3 이동·자세 전환 애니메이션은 제작하지 않았다.

## v0.8 둥근 외형 수정 후 재확인

- 기본 토끼의 둥근 체형·연속 팔다리·커지고 가까워진 눈을 적용한 결과를 재확인했다. 기존 구도·조명을 유지했고, 수정 전 이미지는 [보존된 비교표](Captures/Stage22/BeforeRoundRevision/Unity-ReviewSheet.png)와 해당 폴더의 개별 이미지로 남겼다.
- 수정된 원본과 FBX의 18개 관절 이름·두 정지 자세를 유지했다. Unity 자동 가져오기·크기·재질 검사와 반복 생성 시 수동 영역 보존 검사를 다시 통과했다.
- Blender 검사에서 두 발 자세의 양발 최저 높이는 0m, 네 발 자세의 앞발은 약 -0.0033m·뒷발은 약 0m로 접지 허용 오차 안에 있다. 각 방향 렌더에서 심한 옷 관통이나 관절 틈은 보이지 않았다. 동작 중 변형은 별도 검증한다.
- 실제 Unity Game 창의 QHD 출력·0.86× 표시에서 Play 모드로 수정 외형이 유지되는 것을 확인했다. 축소 렌더에서도 눈과 귀의 실루엣을 확인했다.
- 사용자 재확인 대기이며 2-2 완료·2-3 착수로 처리하지 않는다.

## 관찰 환경과 결과

- Unity 2022.3.20f1, Windows DX11, URP 14.0.10.
- 실제 `TinyDays - RabbitStudy` 편집기 창의 Game 탭에서 확인했다. Game 출력 QHD 2560×1440, 표시 배율 0.86×.
- Play 버튼으로 실제 Play 모드에 진입해 두 발·네 발 정지 자세, 작업복과 URP 재질이 유지되는 것을 확인했다. Play 모드 종료 후에도 동일한 검토 화면이 유지된다.
- [Blender 비교표](Captures/Stage22/Blender-ReviewSheet.png)와 [Unity 비교표](Captures/Stage22/Unity-ReviewSheet.png)의 정면·측면·후면·비스듬한 구도 및 축소 렌더를 관찰했다. 실루엣·방향이 대응하고 심한 복장 관통·형태 붕괴는 보이지 않았다. 렌더러와 조명 차이 때문에 명암은 완전히 같지 않다.
- 단일 관절 모델을 두 정지 자세로 비교한 결과다. 움직이는 중의 관절·복장 품질과 소품 접촉은 이후 검증한다.

## 검증 구분

자동 검사 근거는 [Stage22Verification.txt](Stage22Verification.txt)에 별도로 기록한다. 비교 PNG는 카메라 렌더이며 실제 Game 창의 스크린샷으로 표시하지 않는다.

이번 확인은 정지 외형 표시 범위다. 자유 카메라 입력, 작은 실제 창에서의 조작, 2-7의 종합 장면 5분 관찰, Windows 실행 파일, 장시간 안정성과 자율 생활은 아직 검증하지 않았다.

사용자가 체형·작업복·두 기본 자세를 확인할 때까지 2-2 완료 및 2-3 착수로 기록하지 않는다.
