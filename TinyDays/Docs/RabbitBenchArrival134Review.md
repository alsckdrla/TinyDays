# v0.134 벤치 착석 준비의 반복 뒷걸음 제거

최신 v0.135는 첫발 중간 착지와 최대 세 걸음1.2초를 사용한다. 이 문서의 두 걸음 고정은 당시 기록이며 `RabbitShortPreparation135Review.md`를 따른다.

갱신: 2026-10-04. 구현·최종 검사·렌더·Windows 빌드 완료. **벤치 두 걸음 착석 준비 사용자 확인 대기**.

## 변경

- v0.133은 물뿌리개 이탈을 수정했지만 벤치 자체의9cm 반복 뒤걸음은 보존했다. 착석 준비점에 닿을 때까지 두 걸음을 다시 시작하던 것이 이번 반복 잔걸음의 원인이다. 자율AI의 행동 판단이 아니라 지정된 벤치 순서 제어의 문제다.
- 안전한 앞쪽 접근/방향 정리 후 준비점까지 약30cm를 한 번의 두 걸음0.8초로 이동한다. 걸음마다 동작을 다시 시작하지 않으며 끝에서 바로 기존 앉기로 이어진다.
- 진입 자세는0.15초 혼합해 팔 전환을 연결한다. 이미 준비점에 있으면 불필요한 두 걸음을 생략한다. 중간 정지 요청은 진행 중인 한 쌍의 안전한 발 디딤을 마친 뒤 대기하며 재요청은 준비 동작을 반복하지 않는다.
- 기존 모델/원본 애니메이션·벤치 비율·앉기/일어서기1.8초·공중 발 휴식과 기본 호흡·눈 깜빡임·카메라를 유지한다. 아트나 저장 장면은 다시 생성하지 않는다.

## 검증과 재개

- `RabbitBenchArrivalChecks.Before`로 변경 전45도1×연속 렌더를 보존했다. `Draft`의 개별 벤치/연결 생활240Hz는 각각 준비 진입 한 번·0.8초 이내와 접지/실제 벤치/소품 충돌을 통과했다.
- 최종 검사: `RabbitBenchArrivalChecks.Finish`.240/30/60/120fps×두 배속, 개별/연결 생활 흐름, 네 준비 위상의 일시정지/취소/반복 요청/재착석과 기존 벤치·물 주기·출입 접지 회귀를 검사한다. 기준은 고정발 이동3.5mm·접촉 간격5mm·침범0.5mm 이하와 관절 길이 유지다.
- 결과: `RabbitBenchArrival134Verification.txt`, `Logs/bench134-final.log`. 렌더는 `Logs/BenchArrival134`, 실행 파일은 `Logs/RabbitHomeLifePlayer/TinyDaysRabbitHomeLife.exe`이며 Data 폴더가 함께 필요하다.
- 최종 검사 `BENCH134_COMPLETE_OK`: 개별/연결16조건 모두 준비 진입 한 번·0.8초 이내. 고정발 이동0.163mm·최대 접촉 간격2.554mm·최저 신발 높이2.399mm·도달 초과0이었다. 네 준비 위상의 중단/재착석도 통과했고 기존 벤치·물 주기·출입 반복/걷기/달리기 회귀와 원본/FBX/저장 장면 해시를 확인했다.
- 실제 빌드의 벤치 자동 실행도 `BENCH_PLAYER_SMOKE_OK`로 통과했다(`Logs/bench134-player.log`). 직접 OS 입력은 수행하지 않았다.
- 전후1×영상은 `Captures/RabbitBenchArrival134/BeforeAfter45.mp4`(왼쪽 이전/오른쪽 수정), 수정 후 세 구도는 같은 폴더의 `After0.mp4`, `After45.mp4`, `After90.mp4`다.15fps·8초 렌더이며 실제 OS 조작 녹화가 아니다.
- 실제 OS 버튼 입력과 사용자 자연스러움 승인은 자동 함수 호출/영상과 구분한다. v0.133 경로 계산 약0.95초 지연은 별도 남은 개선 대상이며 이번 작업에서 해결했다고 기록하지 않는다.
