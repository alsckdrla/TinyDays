## 원인과 구현 초안

- 사용자 영상: `Docs/Check/Tiny Days HomeLife Walking chk 2026-10-03 15-10-07.mp4`. 접근과 돌아서는 구간에서 큰 웅크림을 확인했다.
- 기존 생활 IK가 대기/이전 보정 단계에서 읽은 다리 길이를 계속 사용했다. 원본은 회전 외에 관절 위치도 위상별로 애니메이션하므로 현재 샘플의 길이를 보존하도록 변경했다. 기본 모델·클립·FBX를 다시 만들지 않는다.
- 거리 기반 걷기 위상을 유지하고 남은 디딤 거리로 미래 위치를 계산한다. 경로의 접선과 실제 몸 회전의 차이를 고려해 착지 방향을 예측한다. 공중 발의 도달 때문에 몸 전체를 낮추지 않도록 분리했다.
- 지지발 접지를 유지하면서 골반 높이/무릎 굽힘을 맞추는 초안은 아직 착지 때 높이가 바뀐다. 추가 관절 늘림으로 해결하지 않는다. `FollowWalkingHeading`을 사용하는 생활 보행에 한정했다.
- 현재 위치 주변 접근 후보를 선택하고 집/화단의 정적 메시 삼각형 경계 및 보관 소품 여유를 검사한다. 원래 보관 자세와 이번 접근 자세는 분리했다. 집기 준비 중 소품은 중심을 유지한 채 바닥 수직축으로 회전한다.

## 자동 검사와 남은 실패

- 이전 진단 최대 추가 골반 하강359.8mm. `Logs/natural129-walk11.log`의 중간 초안은 약8mm 하강, 추가 지지 무릎 굽힘 약10.213도다. 전체 흐름 완료 로그는 자세 검사 PASS와 다르다.
- 같은 진단의 240Hz 표본에서 착지 경계의 실제 골반 높이 변화 약28.5mm가 남았다. 자연스러운 보행으로 승인할 수 없다. 골반 수평 정렬을 추가한 다음 실험(walk12)은 악화되어 제거했다.
- `natural129-posture3.log` 단계에서160개 일반/운반 회전 및8개 중단/재개가 통과했지만 이후 착지 예측을 변경했다. 최신 코드 전체 재검사가 필요하다.
- `natural129-draft3.log`: 내려놓기 반대 방향180도에서 도달 초과 약35mm. 추가 상체 숙임으로 가리려던 실험은 제거했다. 따라서 이 로그의 일부 방향 성공도 현재 코드의 최종 검증으로 사용하지 않는다.
- `natural129-flow1.log`: 새 보관점 접근 후 벤치 출발 약0.196초에 Shoes와 보관 소품이 겹친다. `RabbitBenchReview.StartConnectedFlow`의 이탈 계산은 기존 고정 접근을 가정했으므로 새 접근 전체를 지원해야 한다.
- `RabbitNaturalWalkChecks.Diagnose`는 진단 기록 함수이며 통과 판정 함수가 아니다. 현재 CSV는 마지막 실험 결과일 수 있으므로 로그 이름/코드 상태를 함께 확인한다. `Pickup`/`Draft`는 미완료 테스트다.

## 사용자 결정이 필요한 항목

내려놓을 때 양손을 붙인 채 보관 방향으로180도 회전하면 팔 교차/도달 문제가 발생한다. **바닥에 놓고 손을 떼는 동안 물뿌리개가 원래 방향으로 자동 정리**되는 방식을 질문했다. 답변 전에는 해당 대안을 확정하거나 구현하지 않는다. 기존1.8초/보관 위치 유지 요구도 이후 검사한다.
