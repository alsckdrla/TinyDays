# Tiny Days 본게임 마스터 플랜 v0.64

작성일: 2026-09-14  
최종 갱신: 2026-09-22
상태: **2-7-1·2-7-2 사용자 확인 완료 / 2-7-3 종합 관찰 진행·보완 사항 발견 / 일부 실제 입력 검증 남음 / 캐릭터 보완 보류 유지**
기준: 기존 게임 기획서 v0.3 + 사용자와 합의한 본게임 방향 및 통합 계획

## 1. 문서의 역할과 운영 원칙

### v0.64 — 출시 이후 장기 확장 구상 기록

- 사용자 첨부의 비주얼·개입·주민 생애·역사 DLC·웹 체험판 구상을 6장에 장기 후보로 보존한다. 비주얼 내용도 현재 본편 아트 기준의 변경이 아니라 장기 확장 방향이다.
- 본편 1.0 범위, 현재 농가·캐릭터·조명과 제작 순서는 변경하지 않는다. 현재 단계는 2-7-3 진행 중이며 신규 게임 구현은 없다.
- DLC 구성·유료 여부·시대·가격·일정·규모·기술 방식은 별도 합의 전 확정하지 않는다.

### v0.63 — 엘리베이터식 카메라 높이 이동

- 가운데 드래그와 Q/E는 카메라를 세계 수직 방향으로만 이동한다. 이동 중 yaw·pitch는 유지되어 틸트가 생기지 않는다.
- 전체 보기에서는 이동한 카메라의 화면 중앙 광선이 닿는 가장 가까운 정적 농가 메시를 다시 목표점으로 삼고 관찰 거리를 갱신한다. 주민과 Backdrop은 제외하며, 유효한 메시 또는 줌 거리 범위를 찾지 못하면 마지막 유효 구도를 유지한다.
- 주민 포커싱은 해제하지 않고 주민을 계속 따라간다. 높이 이동은 시선을 고정하므로 주민의 화면상 위치가 조금 변할 수 있다. 왼쪽 패닝·우클릭 회전·휠 줌·지면 경계·가림·Home 규칙은 유지한다.
- 자동 검사와 Windows 검토 빌드를 통과했다. 실제 Unity Game 창·독립 실행 창의 엘리베이터 감각과 사용자 확인은 2-7-3에 남긴다.

### v0.62 — 휠 확대/축소 방향 반전

- FarmStudy의 카메라 휠 방향을 반전한다. 휠을 위로 올리면 멀어지고, 아래로 내리면 가까워진다.
- 1m 최소 거리·최대 줌아웃·주민 포커싱·가림·지면 경계·시간대 패널 내부 스크롤 방향은 유지한다.
- 자동 검사와 Windows 검토 빌드를 통과했으며 실제 독립 실행 창의 휠 입력과 사용자 확인은 2-7-3에 남긴다.

### v0.61 — 가운데 드래그 높이 이동·우클릭 회전

- 왼쪽 드래그는 수평 패닝으로 유지한다. 가운데 드래그의 세로 이동과 Q/E는 카메라 위치의 높이 오프셋만 조절하며, 전체 보기의 정적 농가 목표점과 주민 포커싱의 몸통 목표점은 이동시키지 않는다. 위로 드래그하면 카메라가 올라간다.
- 우클릭 드래그만 화면 중앙 목표점 기준 회전을 시작한다. 카메라는 높이 오프셋 중에도 목표점을 계속 바라보므로 회전·줌·패닝에서 화면이나 위치가 튀지 않는다.
- Home·전체 보기·주민 포커싱·고정 비교 구도 전환은 높이 오프셋을 초기화한다. UI 입력 차단, 지면 경계 패닝, 가림 반투명과 1m 줌은 유지한다.
- 자동 검사·기존 UI/주민 가림 회귀 및 Windows 검토 빌드를 통과했다. 실제 Unity Game 창과 독립 실행 창에서 가운데 드래그·우클릭 회전·포커싱 구도 및 Home 복귀는 사용자 확인 대기다.

### v0.60 — 카메라 목표점과 농가 지면 패닝 경계

- 전체 보기에서 가운데 또는 우클릭 드래그 회전을 시작하면 화면 중앙 광선이 닿는 가장 가까운 정적 농가 메시를 목표점으로 삼는다. 주민과 넓은 베이지색 Backdrop은 목표에서 제외하며, 현재 카메라 위치·화면 구도·기존 줌 범위는 유지한다. 대상이 없으면 현재 목표점을 유지한다.
- 주민 포커싱은 주민 몸통 기준점을 회전·추적 목표로 계속 사용한다. 주민 이동 중에도 사용자가 만든 구도 오프셋과 카메라-주민 사이의 25% 가림 반투명을 유지한다.
- 마우스·키보드 패닝은 수평 지면과 평행하게 이동한다. 전체 보기 목표점과 포커싱 오프셋은 실제 Spring meadow 메시 범위 안에서만 이동하며, 경계에서는 해당 방향 이동만 멈춘다. 높이(Q/E)와 건물 위 목표의 높이는 유지한다.
- 생성 메시 기반 자동 검사와 기존 UI·주민 가림 회귀, Windows 빌드를 통과했다. 실제 Unity Game 창과 독립 실행 창의 회전 중심·경계 입력·사용자 확인은 2-7-3에서 별도로 남긴다.

### v0.59 — 우클릭 드래그 카메라 회전

- 가운데 드래그 회전을 유지하고 우클릭 드래그도 FarmStudy 카메라 회전에 연결한다. UI 위에서 시작한 우클릭은 회전하지 않는다.
- 가운데·우클릭의 누름 상태를 따로 관리해 두 버튼을 함께 누른 경우 한쪽을 놓아도 다른 쪽을 누르는 동안 회전을 유지한다. Esc·색상 선택창·설정창·앱 포커스 상실·메뉴 조작 시 회전을 해제한다.
- 자동 검사와 Windows 빌드를 통과했으며 실제 독립 실행 창의 우클릭 입력과 사용자 확인은 대기다. 2-7-3은 진행 중이다.

### v0.58 — WASD·화살표 키 카메라 이동

- Q/E 높이 조절을 유지하고 W/A/S/D 및 화살표 키로 화면 기준 평면 이동을 제공한다. 카메라 회전 뒤에도 W는 화면 위, D는 화면 오른쪽으로 이동한다.
- 대각선은 정규화하며 이동 속도는 현재 줌 거리와 연동한다. 주민 포커싱 중에는 추적을 유지한 채 구도 이동량에 더하고, 전체 보기에서는 기존 카메라 중심을 이동한다.
- 색상 선택창·Esc 설정창·시간 입력의 기존 카메라 입력 차단과 Home·줌·회전·마우스 패닝 규칙을 유지한다. 자동 검사와 Windows 빌드를 통과했으며 실제 키 입력과 사용자 확인은 대기다.

### v0.57 — 작은 창 UI 버튼 크기·줄바꿈 보완

- 모든 조작 버튼의 기준 높이를 42로 통일한다. 하단 6개 메뉴는 화면 폭 740px 미만에서 3열·2줄로 전환해, 기존보다 약 1.5배 큰 버튼 상태에서 줄바꿈한다.
- 상단 안내의 여백과 시간대 비교 버튼을 새 기준에 맞추고, 시간대·하루 길이·배속·그림자·색상 미리보기와 색상 선택창의 버튼을 같은 높이로 맞춘다.
- 시간대 패널은 짧은 창에서 버튼을 축소하지 않고 내부 마우스 휠 스크롤을 사용한다. 클릭 판정·카메라 입력 차단도 현재 스크롤 위치를 따른다.
- 자동 레이아웃 검사 통과. 실제 독립 실행 창과 사용자 확인은 대기이며 2-7-3은 진행 중이다.

### v0.56 — 대지 바깥 지하에서도 실제 땅 반투명 유지

- 카메라가 농가 지표면보다 낮으면 대지 안팎·주민 포커싱 여부와 관계없이 Spring meadow·Meadow foundation·Backdrop을 불투명도 25%로 약 0.2초에 걸쳐 전환한다. 수직 위에 땅이 있는지를 요구하던 조건을 지표면 높이 기준으로 바꾼다.
- 땅과 아래쪽 면의 형태는 보존한다. 지상 복귀 시 원래 재질로 복원하며 Backdrop 자체의 하부·내부 예외는 유지한다.
- 2-7-3 보완·사용자 확인 대기. 자동 검사·농가 렌더·실제 게임 창 입력을 별도로 기록한다.

### v0.55 — 배경 바닥 반투명 수정 및 Plane 처리 원복

- 넓은 베이지색 Backdrop의 크기·위치·색감은 유지한다. 카메라가 농가 지하 또는 Backdrop 영역 아래에 있으면 불투명도 25%로 약 0.2초에 걸쳐 전환하고 지상 복귀 시 원래 재질을 복원한다. 농가 영역 밖에서도 Backdrop 아래에서는 적용한다.
- 배경 전용 셰이더에 실제 알파 블렌딩과 깊이 쓰기 전환을 적용한다. 시간대별 색상과 편집값은 반투명 중에도 유지한다.
- v0.54의 Plane 진단은 실제 베이지색 Backdrop 문제와 다른 대상이었다. 당시 추가한 이름 기반 Plane 등록·바닥 분류 및 전용 검사는 원복했다. 실제 오브젝트와 수동 영역은 보존한다.
- 자동 수치 검사와 뒤쪽 검증 물체가 비치는 GPU 렌더 검사를 통과했다. 실제 독립 실행 창 입력과 사용자 확인은 별도 대기이며, 2-7-3은 진행 중이다.

### v0.53 — 2-7-3 종합 관찰 진행

- 사용자 확인으로 시계·Day 보완을 마무리하고 2-7-3 검증을 진행했다. 본게임 런타임 구현은 이번 검증에서 변경하지 않았다.
- 조명·시간·배속·그림자 자동 검사를 재실행해 통과했다. 기존 캡처 파일 잠금은 재발하지 않았다.
- 독립 Windows 창의 1280×800·800×600·600×900·최대화 표시와 5분 이상 자동 순환을 실제 화면으로 관찰했다. Day 증가, 메뉴 숨김 중 시계, 주민 포커싱 가림 및 Home 복귀를 확인했다.
- 세로 전체 구도에서 오른쪽 창고·대지 일부가 화면 밖으로 나가며 작은 창의 안내문 크기와 Esc 패널 글자 대비가 아쉽다. 보완 후 재확인이 필요하다.
- 자유 회전·Q/E·정확한 1m 도달·내부 진입의 실제 입력 및 Unity Editor Game 창 확인은 남아 있다. 2-7-3을 완료 처리하지 않는다. 상세는 `Stage273Observation.md`를 따른다.

### v0.52 — Day 표시 하단 잘림 보완

### v0.51 — Day 표시 추가 확대

### v0.50 — Day 표시 미세 확대

### v0.49 — Day 표시 비율·간격

- Day 표시는 시계 바로 아래로 올리고 글자 크기를 기존의 약 60%로 줄인다. 시계의 배경 없음·글자 그림자·상단 중앙 정렬과 시간·날짜 규칙은 유지한다.

### v0.48 — 상단 시계 가독성

- 상단 시계의 네모 배경을 제거하고 시각·Day 글자만 표시한다. 두 글자는 반투명 짙은 그림자를 먼저 그린 뒤 본문을 그려 밝은 낮에도 읽히게 한다.
- 시각은 흰색, Day는 차분한 밝은 크림색을 유지한다. 시계 높이와 Day 영역 하단 여백을 늘려 잘림을 방지한다.
- 상단 중앙 정렬, 메뉴 숨김 중 표시, 비클릭·비차단, 시간·Day 진행 규칙은 v0.47 기준을 그대로 따른다.

### v0.47 — 상단 시계·날짜 표시

- 화면 상단 중앙에 24시간제 시각과 Day 번호를 표시한다. 메뉴를 숨겨도 유지하며, 클릭 기능이나 카메라 입력 차단은 없다.
- 시작은 Day 1 12:00이다. 자동 시간 순환이 자정을 통과할 때마다 Day가 증가한다. 시간대 고정·색상 편집은 시각만 바꾸고 Day는 유지한다.
- 하루 길이·배속·일시정지와 같은 조명 시계를 사용하며, 처음부터는 Day 1 12:00 자동 순환으로 되돌아간다. 재실행 저장은 이번 범위에 포함하지 않는다.
- 검증은 자정·다일 진행·고정 시 Day 유지·처음부터, 메뉴 숨김 및 창 크기별 실제 표시를 구분해 기록한다.

### v0.46 — 하루 길이·재생속도 조절

- 시간대 비교 패널에서 1배속 기준 하루 길이를 1~120분 정수로 입력해 적용한다. 5·10·20·30분 추천 버튼, 0.5·1·2·4배속 버튼을 제공한다. 기본은 5분·1배다.
- 배속은 주민 이동·대기·동작 및 자동 낮밤에 함께 적용한다. 실제 하루 소요 시간은 설정 분/배속이며 패널에 표시한다. 시간 고정 중에는 주민만 해당 배속으로 움직인다. 카메라·UI·가림 전환 속도에는 적용하지 않는다.
- 변경 시 현재 시각·주민 위치를 초기화하지 않는다. 일시정지 중 설정을 바꿔도 정지 상태를 유지한다. 처음부터는 현재 하루 길이·배속·정지 여부를 유지하고 낮 12시 자동 모드·주민 0초로 복귀한다.
- 이번 값은 검토용 설정이며 본게임 밸런스 확정이 아니다. 실행을 새로 시작하면 5분·1배로 시작하며 기존 사용자 색상 저장은 유지한다. 프로토타입의 16배 성능 미달·최적화 보류와 별개다.

이 문서는 Tiny Days 본게임의 작업 기준이다. 매 작업 전에 읽고 현재 범위, 미정 사항, 통과 기준을 확인한다. 프로토타입의 마스터 플랜과 단계 번호는 별개다.

큰 구분은 **1~6단계**, 세부 구분은 **2-1, 2-2…**로 표기한다. 이 문서의 절 번호와 제작 단계 번호는 구분한다.

- **확정 방향:** 게임의 정체성과 판단 원칙. 변경은 사용자와 합의한다.
- **1.0 범위:** 채택한 기능의 범위이며, 구현 완료를 의미하지 않는다. 세부 수치와 목록은 별도 합의한다.
- **장기 후보:** 비전을 보존하기 위한 목록이다. 구현 승인이나 출시 약속이 아니다.
- **미정 사항:** 관련 기능 착수 전 합의가 필요하다. 예시·후보·프로토타입 값을 확정값으로 사용하지 않는다.
- 새 요청이 현재 기준을 바꾸면 충돌 내용을 알리고 합의한 내용을 이 문서에 반영한 뒤 작업한다.
- 작업 결과, 남은 검증과 사용자 확인 상태를 이 문서에 갱신한다. 과거 기록과 최신 기록이 충돌하고 근거가 불분명하면 사용자에게 확인한다.
- 기존 수동 자산과 변경 사항을 보존한다. Unity 2022.3.20f1 / Blender 5.2.1을 임의로 업그레이드하지 않는다.
- 문서와 참고 이미지는 Git 관리 대상으로 유지한다. 다른 PC로 이전할 때 최신 코드·기획·필요 자산이 실제 커밋·푸시되었는지 확인한다. 파일 생성만으로 커밋·푸시 완료라고 보고하지 않는다.

작업 요청은 먼저 이해한 내용을 요약하고 승인 후 수정한다. 이미 합의한 계획의 실행 요청은 바로 진행한다. 사용자가 요청하기 전에는 수정 디테일을 나열하지 않고, 작업 후에는 **작업 / 확인 / 다음**으로 간결하게 보고하며 다음 작업의 권장 모델과 플랜 모드 여부를 안내한다.

## 2. 게임 목표와 정체성 — 확정 방향

**귀여운 동물 주민이 스스로 생활하고 발전하는 모습을, 화면 한켠에서 편안하게 지켜보는 작은 디오라마 게임.**

가제는 Tiny Days. 장르는 힐링형 방치 시뮬레이션·생활 관찰·마을 성장 시뮬레이션이다. Windows / Steam을 우선하며 약 1달러 수준의 저가 출시를 목표로 한다. 정확한 판매가는 추후 결정한다. 개발 환경은 Unity + Blender + Codex다.

### 경험 목표

| 시점 | 목표 경험 |
|---|---|
| 처음 10분 | 예쁘다. 귀엽다. |
| 약 30분 | 화면 한켠에 계속 켜두고 싶다. |
| 며칠 뒤 | 이전보다 생활과 풍경이 조금 달라졌다. |

콘텐츠 양보다 가격이 아깝지 않은 시각적 매력, 안정적인 생활, 천천히 축적되는 변화를 우선한다. 며칠 뒤의 변화는 1.0에서 실제 실행한 시간 동안 누적된 변화다.

### 디자인 원칙

1. 실행해 두는 것 자체가 즐거울 만큼 예쁘고 편안해야 한다.
2. 주민은 환경·자원·계절·날씨·성격·필요를 바탕으로 스스로 생활한다.
3. 플레이어에게 필수 퀘스트나 반복 과제를 요구하지 않는다. 원할 때 방향을 제시하고 꾸민다.
4. 지형 배치·날씨·주민·작은 사건의 조합으로 매번 조금씩 다른 일상을 만든다.
5. 레벨 숫자보다 생활과 풍경의 변화로 발전을 표현한다.
6. 농땡이·감상·실수·놀이 등 비효율적인 행동도 주요 콘텐츠다. 큰 손해를 강요하지 않는다.
7. 성장할수록 면적과 생산량뿐 아니라 여가와 생활의 질이 풍요로워진다.

새 기능은 마을을 더 예쁘고 살아 있게 만드는지, 새로운 생활 장면을 만드는지, 기존 시스템과 결합하는지, 불필요한 숙제를 만들지 않는지로 판단한다.

## 3. 세계와 1.0 성장 범위

1.0은 마법 없는 가상의 저기술 농경세계다. 특정 시대의 중세 유럽을 정확히 재현하기보다 따뜻하고 담백한 농촌 생활을 표현한다.

**채집 → 초기 정착 → 농경 → 안정된 농가 → 부농 → 작은 농촌마을**

첫 출시는 한 마을의 생활을 깊게 만드는 데 집중한다. 주변 어둠 속 땅을 조금씩 밝혀 영역을 넓힐 수 있지만 여러 독립 마을을 운영하는 기능은 장기 후보다. 고정 레벨 상승이나 강제 엔딩 대신 생활 안정과 성숙을 지향하며, 성숙의 구체적 조건과 1.0 규모는 미정이다.

## 4. 1.0 확정 범위와 행동 원칙

### 4.1 플레이어 개입과 자율 건설

- 시작할 때 마을의 큰 성장 방향을 선택하고 이후 바꿀 수 있다. 변화는 서서히 생활에 반영된다. 방향 선택지 목록은 미정이다.
- 주민 직접 명령을 기본 진행 방식으로 삼지 않는다.
- 플레이어는 장식을 배치하고 건물 외형을 변경한다. 건물 위치를 직접 지정하거나 완공된 건물을 재배치하는 기능은 현재 확정 범위에 포함하지 않는다.
- 주민이 필요와 주변 상황을 보고 건설과 위치를 결정한다. 기존 장식을 보존할 수 있는 위치를 찾고, 적합한 공간이 없으면 건설을 보류하고 알린다.
- 장식 편집의 접근성·통행 규칙과 알림 방식은 착수 전에 합의한다.

### 4.2 시작 지형과 주변 확장

- 전체 세계를 처음부터 공개하지 않고 정착지 주변만 보여준다.
- 검증된 농경 지형 틀 안에서 자연·자원 배치를 달리한다. 틀의 종류·생성 방식·자원 분포 규칙은 미정이다.
- 주민이 주변 땅 확장을 제안하면 플레이어가 열 방향을 선택한다.
- 응답이 없으면 땅 확장은 기다리되 현재 영역에서 생활과 가능한 질적 성장은 계속된다. 선택 대기를 마을 전체 정지나 필수 과제로 만들지 않는다.
- 어둠은 미공개 영역을 표현하는 방향이며 마법 세계관을 뜻하지 않는다. 탐색 연출·확장 조건·비용·한계는 미정이다.

### 4.3 주민·성격·생활

- 여러 종류의 담백한 의인화 동물을 사용한다. 종과 성격·직업은 독립적이다.
- 주민은 생산 유닛이 아니라 관찰과 애착의 중심이다. 성향·취향·현재 상태와 환경에 따라 다른 행동을 한다.
- 작은 교류, 좋아하는 장소, 감상과 여가, 가벼운 실수와 생활 소동을 포함한다.
- 후보 장면: 인사, 함께 쉬기, 일몰 감상, 처마 아래 비 구경, 낮잠, 물건을 떨어뜨렸다 줍기. 예시는 최종 행동 목록이 아니다.
- 의도한 생활 소동과 이동·예약 오류를 구분한다. 영구 정체나 경로 실패를 귀여운 실수로 정당화하지 않는다.
- 2단계 대표 주민은 토끼·곰·여우다. 본게임 전체 종·직업·성격 목록과 특성 개수, 행동 빈도는 미정이다. v0.3의 성격 2~3개도 최종 수치로 확정하지 않는다.
- 두 발 생활을 기본으로 하며 신남·호기심 같은 특별한 순간에 네 발 움직임을 사용하고, 평소에도 가끔 섞는다. 작업·운반 중의 자세 전환도 귀여운 생활 연출로 활용한다.
- 물건을 내려놓고 다시 집는 과정까지 보여줘 자세와 소품의 관계를 자연스럽게 연결한다. 소동은 잠깐의 변화 뒤 스스로 수습한다.
- 먼저 토끼로 두 발·네 발 전환을 검증하고 곰·여우는 체형과 움직임에 맞춰 별도로 확인한다. 발생 빈도와 종별 행동 목록은 장면 비교 후 합의하며, 최종 자율 행동 확률은 아직 정하지 않는다.
- 아이·가족·출산·노화·세대교체·확장된 관계는 1.0에서 제외하고 후속 후보로 둔다.

### 4.4 생산·부족·자율 발전

- 채집·농경·운반·저장·소비를 생활 행동과 연결한다.
- 소규모 가축의 간단한 돌봄과 생활 반응을 포함한다. 종·생산물·수량은 별도로 합의한다.
- 자원·시설·환경·주민·선택한 방향을 바탕으로 필요한 생산과 건설이 일어난다.
- 예시 흐름: 식량 부족 → 채집·농경 증가 → 생산 회복 → 저장 필요 증가 → 저장시설 확대. 정확한 조건과 수치는 미정이다.
- 부족하면 성장이 느려지고 주민이 적응·회복한다. 굶주림에 따른 사망이나 마을 붕괴는 없다.
- 전쟁·범죄·잔혹한 사건·심각한 싸움·강한 경쟁은 1.0에서 제외한다.
- 정원·쉼터·생활 공간과 여가가 늘어나는 질적 성장을 포함한다. 구체적 시설 목록과 해금 조건은 미정이다.
- 최초의 집·오래된 나무 같은 마을의 흔적을 남기는 방향을 유지한다. 보존 대상과 재건축·꾸미기와의 관계는 별도 합의한다.

### 4.5 시간·계절·날씨

- 새벽·아침·낮·오후·일몰·밤의 빛과 생활 변화를 표현한다.
- 사계절을 적용하고 생활과 생산에도 영향을 준다. 봄의 파종, 가을의 수확, 겨울의 실내 활동 등은 구체화할 예시다.
- 기본 날씨는 **맑음·흐림·비·눈**이다. 강한 비·안개·독립적인 바람 상태·한파·더위·가뭄 등 추가 날씨는 후속 후보로 둔다. 풍경의 작물 흔들림은 별개다.
- 날씨에 대한 행동 반응을 포함한다. 물웅덩이·적설·발자국처럼 오래 남는 흔적의 종류와 구현 범위는 미정이다.
- 일시정지와 시간 배속을 지원한다. 하루·계절 길이, 배속 범위·정확한 속도는 미정이다.
- **1.0은 게임 실행 중에만 진행한다.** 종료 중 진행은 포함하지 않는다.

### 4.6 성장 설정

| 설정 | 의도 |
|---|---|
| 자율 성장 | 선택한 방향에 따라 생활과 발전을 이어간다. |
| 보존 모드 | 전체적인 풍경과 규모를 유지하면서 생활은 이어간다. |
| 일시정지 | 시간을 멈춘다. |

보존 모드에서 허용할 건설·재배·장식·계절 변화와 전환 방식은 구현 전에 합의한다. 완만한 성장의 별도 모드는 후속 검토 대상으로 둔다.

### 4.7 UI·창·정보

- 화면 한켠에 계속 켜두기 좋은 최소 UI와 넓은 마을 화면을 지향한다.
- 카메라는 좌우 360도 회전, 상하 회전, 높낮이 이동, 평면 이동, 확대/축소와 기본 구도 복귀를 지원한다. 높낮이 이동은 상하 회전·확대와 별도의 조작으로 제공한다.
- 비스듬히 내려다보는 미니어처 구도를 기본으로 하되 고정하지 않는다. 원근 카메라와 -90~75도 회전을 유지하고, v0.18에서는 지면·건물도 자유롭게 통과하며 가리는 환경 개체를 투명화한다.
- 2-7 검토 조작은 휠 거리 조정, 왼쪽 드래그 화면 기준 패닝, 가운데 드래그 회전, Q/E 높낮이 이동, Home 최초 전체 구도 복귀로 한다. 감도와 가림 처리는 문서 상단 v0.18 합의를 따른다. 출시 확정 수치는 사용자 확인으로 정한다.
- 자유로운 창 크기와 가로세로 비율에 대응한다. 지원 최소 크기와 구도 처리 방식은 미정이다.
- 필요한 정보는 요청했을 때 표시하고, 자원은 과도한 숫자보다 ‘식량: 넉넉함’ 같은 생활 상태 표현을 우선한다.
- 데스크톱 모드·항상 위·입력 무시·창 위치와 크기 저장의 세부 범위는 후속 검토한다.

### 4.8 사운드·저장·실행 품질

- 환경음을 중요한 힐링 요소로 취급한다. 바람·새·물·비·가축·생활 작업음 등은 음원 구성 후보다.
- 전체 사운드·BGM·효과음 켜기/끄기, BGM·효과음 개별 볼륨과 재실행 후 설정 유지를 제공한다.
- BGM을 끄고 환경음을 들을 수 있는 구성을 검토한다. 환경음 별도 채널·볼륨 여부, 기본값·음원 확보 방식은 미정이다.
- 안정적인 저장·불러오기와 진행 상태 복원을 제공한다. 형식·저장 시점·백업·호환 정책은 구현 전에 합의한다.
- 실제 Windows 실행 파일에서 입력, 창 크기 변경, 장시간 실행, 주민 정체 복구, 사운드 설정 유지를 검증한다.

## 5. 비주얼 기준

참고 이미지: [Tiny Days 참고이미지_01.png](<References/Tiny Days 참고이미지_01.png>)

**Low-poly / Miniature / Diorama / Warm / Soft / Calm / Understated / Living World**

- 비스듬히 내려다보는 조망, 단순한 입체 형태, 읽기 쉬운 실루엣을 사용한다.
- 따뜻한 햇빛과 부드러운 그림자, 초록·노랑·흙색의 조화를 참고한다. 일출과 일몰을 대표 장면으로 만든다.
- 얼굴 표정보다 몸짓과 동물별 실루엣을 중시한다. 과도한 SD 비율이나 캐릭터 상품 느낌은 피한다.
- 기본 토끼는 근육질 느낌이 없는 둥글고 부드러운 체형으로 만든다. 짧고 통통하게 이어지는 팔다리, 둥근 배와 완만한 어깨, 더 크고 간격이 좁은 눈으로 귀여운 힐링 인상을 우선한다. 담백한 미니어처 분위기와 작업복 색상은 유지하며 머리를 과도하게 키우지 않는다.
- 추가 외형 합의: 입 주변의 두 볼록한 부분을 더 작게 하고 눈을 한 번 더 키워 간격을 좁힌다. 어깨·소매는 몸통에서 자연스럽게 이어지도록 만든다. 네 발 기본 자세는 앞발로 낮게 받치고 뒷다리를 몸 아래로 접은 토끼다운 자세다. 머리·목·등·엉덩이를 부드럽게 연결하고 꼬리는 엉덩이 뒤에 위치시킨다.
- 눈·코·수염 패드는 [사용자 얼굴 스케치](References/RabbitFace_UserSketch_2026-09-14.png)를 기준으로 한다. 눈 전체 크기·위치·간격은 유지하고 아이보리색 흰자 안에 눈 크기의 약 75%인 둥근 검은 눈동자를 정면 방향으로 배치한다. v0.10의 한쪽 흰자 및 직선 분할 방식은 교체한다. 작은 둥근 코 아래로 두 갈래 수염 패드가 내려오며 아래쪽은 둥글게 한다. 기존 색상과 머리·귀·몸·복장·기본 자세를 유지하고 파란 선을 외형 색상으로 적용하지 않는다. 시선·표정 애니메이션은 이번 범위에 포함하지 않는다.
- 울타리·밭·길·생활 소품의 밀도로 생활감을 만들되 작은 창에서도 주민 행동이 읽혀야 한다.
- 밤에는 차가운 주변색과 따뜻한 창문·불빛을 함께 사용한다.
- 작물·나뭇잎·물결·연기·주민 몸짓 등 작은 움직임이 지속되는 풍경을 지향한다. 개별 표현의 채택과 우선순위는 해당 단계에서 정한다.
- 풀·꽃·농작물·나무에는 우선 약한 바람에 따른 종류별 흔들림을 적용한다. 바람 세기 변화·돌풍·날씨 연동은 후속 합의 대상으로 둔다.
- 이미지의 차량·아스팔트·현대 시설·대형 숫자 UI를 1.0 확정 요소로 삼지 않는다. 시설은 저기술 농경세계, UI는 최소 표시 원칙을 따른다.
- 2단계는 토끼·곰·여우, 참고 이미지 정도의 담백한 미니어처 비율, 간소한 농촌 작업복을 기준으로 제작한다. 카메라는 비스듬한 기본 구도에서 좌우 360도·상하 회전, 높낮이·평면 이동, 확대/축소와 기본 구도 복귀를 제공한다. 여러 방향과 높이에서 주민·건물·소품의 외형과 가독성을 확인하며, 최종 외형·재질·밀도·구체적인 카메라 수치는 사용자 확인으로 확정한다.

v0.3에 제시된 [Egg, Inc. 플레이 영상](https://www.youtube.com/watch?v=74Vym3T4BPo)은 분위기 참고 출처로 보존한다. 이번 통합에서 직접 확인한 시각 자료는 위 로컬 이미지이며, 영상의 세부 장면을 검증한 것으로 기록하지 않는다.

### 6.1 장기 확장의 공통 철학과 비주얼

아래 6.1~6.7은 2026-09-22 사용자 제공 구상을 정리한 **출시 이후 후보·구현 미승인** 기록이다. 현재 본편의 비주얼 기준과 출시 범위를 대체하지 않는다. 구체적 행동·연령·인원·시대·콘텐츠 묶음은 설명용 예시다.

- 작은 세계는 플레이어가 관찰하지 않아도 스스로 살아가며, 플레이어는 가끔 개입하고 특정 주민에게 애착을 갖는 관찰자다. 이 철학을 일상에서 주민의 일생과 역사 관찰까지 확장한다. 이는 1.0 오프라인 진행 채택을 의미하지 않는다.
- 초기 참고 이미지의 Low-poly / Miniature / Diorama / Warm / Soft / Calm / Understated / Living World를 장기 확장의 비주얼 방향으로 검토한다. 살아 움직이는 작은 디오라마를 지향한다.
- 현실의 형태·비율을 단순화한 축소 모형, 큰 실루엣과 색 덩어리, 절제된 텍스처·장식을 우선한다. 넓은 잔디·농지·길의 여백을 활용하고 꽃·소품·식생으로 화면을 빽빽하게 채우지 않는다. 모델의 세부보다 색과 조명으로 아름다움을 만든다.
- 새벽의 차분한 색·옅은 안개, 아침의 부드러운 햇빛, 밝은 낮, 오후의 긴 그림자, 황금빛 일몰, 차가운 밤과 따뜻한 인공조명을 후보로 보존한다. 현재 합의된 조명값이나 저장된 사용자 색을 변경하지 않는다.

### 6.2 Interactive Living World — 작은 개입과 반응

- 손가락 형태 커서로 주민·땅·물건을 건드리거나 날씨·자연현상에 개입하는 방식을 검토한다. 작은 개입 → 서로 다른 주민 반응 → 주변으로 반응 전파 → 일상 복귀를 목표로 한다.
- 멈칫함·고개 돌림·두리번거림·피하기·구경·반복 접촉 후 자리 떠나기 등을 성격과 현재 상황에 따라 달리한다. 표정보다 몸 방향·자세·속도·타이밍으로 감정을 표현한다.
- 간단한 단기 상태로 반복 개입에 대한 반응이 변하게 한다. 호기심 → 회피 → 자리 이동 등은 후보이며 복잡한 기억 시스템을 선행 제작하지 않는다.
- 비를 내리거나 위치를 골라 번개를 떨어뜨리는 개입을 검토한다. 주민 상해보다 놀람·생활 반응·회복에 초점을 둔다. 농기구 챙기기·빨래 걷기·비 피하기·우산 사용·비 구경·낙뢰 방향 보기·뒤늦게 살펴보기 등은 예시다.
- 눈·강풍·폭우·더위·안개·계절 변화와 발자국·물웅덩이 등의 흔적도 후보로 둔다. 자연 발생과 플레이어 개입의 관계·빈도·제한은 미정이다.
- 개입 없이도 일·운반·대화·휴식·낮잠·낚시·감상·농땡이·놀이·인사·물건 전달이 이어져야 한다. 무지개 함께 보기나 늘 같은 꽃을 구경하는 습관처럼 드문 장면을 발견하는 경험 자체도 보상으로 검토한다.

### 6.3 Personal Living Story — 관심 주민의 일생

- 관심 주민 지정·이름 붙이기·주요 사건 자동 기록을 검토한다. 현재 카메라 포커싱 기능과 구분되는 장기 애착 기능이다.
- 진로 등의 중요한 순간에 권유하거나 스스로 결정하도록 둘 수 있다. 즉각적인 명령·결과 대신 관심 → 관찰 → 연습 → 실패·재도전 → 장기 변화의 과정을 보여준다. 권유와 다른 결과나 원래 직업으로의 복귀도 가능하다.
- 하루 일과부터 직업·관계·이사·주거·생활 수준 변화, 어린 시절·성인·중년·노년까지 관찰하는 방향이다. 생애 속도와 선택지 표시 방식은 미정이며 필수 응답이나 반복 숙제를 만들지 않는다.
- 관심 주민을 계속 따라다니지 않아도 기록과 정체성이 남고, 다른 지역에서 성장하거나 이주한 주민과 우연히 재회하는 경험을 검토한다. 연령별 기록과 목공 입문·작업장 개업·제자·은퇴 등의 사례는 확정 사건이 아니다.

### 6.4 여러 지역의 생활 연속성과 연속 관찰

- 카메라가 떠나도 주민 데이터를 초기화하지 않고 거리·시간에 따라 계산 정밀도를 달리하는 방향이다.
- 가까운 지역은 AI·이동·애니메이션·경로 탐색을 계산한다. 인접 지역은 주민 ID·위치·행동·대상·시작 시각·다음 목표 등을 보존해 경과 시간에 맞춰 생활을 이어가는 방식을 검토한다.
- 먼 지역은 인구·생산·식량·경제·발전·지역 상태를 경량 계산하고 방문 시 풍경과 생활에 반영한다. 군사 계산은 역사 확장에 한정된 후보이며 본편 기능이 아니다.
- 주민 → 마을 → 지역 → 압축된 세계 지도로 가능한 한 연속적으로 확대·축소하는 관찰을 검토한다. 실제 구름층을 통과하는 연출로 LOD·지역 스트리밍·주민 표시·상세 모델 전환을 자연스럽게 감추는 구상이다.
- 실제 기술 구조·전환 거리·저장 규격·성능 목표는 확장 착수 전에 검증한다. 현재 단계에서 대규모 범용 시스템을 미리 구현하지 않는다.

### 6.5 Historical Living Diorama — 역사 확장·유료 DLC 후보

- 전략·전쟁 게임으로 전환하기보다 과거의 생활과 역사적 사건을 살아 움직이는 디오라마로 관찰한다. 시각적·공간적 역사 이해라는 교육적 가치를 목표로 검토한다.
- 산맥·강·해안·도시의 특징을 살린 압축된 한반도를 후보로 둔다. 고조선·삼국·통일신라와 발해·고려·조선·이후 시대에 걸쳐 같은 땅의 마을·농지·도로·성곽·건축·복식·도구·교통 등이 변하는 방향이며, 제작 시대와 범위는 미정이다.
- 사건은 별도 미니게임보다 해당 시간·장소의 세계 사건으로 표현한다. 임진왜란·한산도대첩은 예시이며 지역·함대·선박·갑판·병사 한 명까지 관찰하는 장기 구상이다. 진형·이동·노 젓기·명령 전달·화포 준비·포격 등도 후보이다.
- 전투는 유혈·신체 훼손 없이 섬광·연기·물기둥·함선 손상·후퇴·인물 움직임으로 표현하는 방향이다. **본편 1.0의 전쟁 제외 원칙은 유지**하며 역사 콘텐츠에 한정해 별도로 합의한다.
- 역사적 큰 흐름은 기록을 따르며 장난스러운 개입으로 주요 인물의 사망이나 전투 결과·역사 분기가 바뀌지 않는 방향이다. 개입의 허용 범위는 별도 결정한다.
- 연도·날짜·시간·시대·옛/현재 지명·사건·인물·군대/함대 이동·진행 경로를 선택적으로 표시하고, 텍스트·아이콘을 모두 숨긴 감상도 검토한다. 타임라인·사건 선택으로 시간과 장소 이동, 같은 장소의 시대별 비교도 후보이다.
- 사람은 실제에 가까운 비율과 최소한의 얼굴·머리카락 표현을 가진 로우폴리 미니어처로 검토한다. 사람/동물 표시 선택도 후보이며 본편 동물 주민 기준을 바꾸지 않는다.
- 사건·지형·지명·건축·복식·갑옷·무기·선박·농업·생활도구·생활사를 조사하고, **확인된 사실 / 연구에 따른 복원 / 불확실한 부분**을 구분한다. AI 조사 결과도 사료·논문·서적·박물관·공공기관 자료로 확인한다.
- 자체 로우폴리 디자인으로 재해석하며 현대 영화·드라마·게임의 특정 디자인을 복제하지 않는다. 사진·도면·복원 이미지의 직접 사용은 별도로 라이선스를 확인한다.
- 시작 시 기록과 연구 기반 재구성이며 일부 연출적 재해석이 있다는 짧은 안내를 검토한다. 자세한 출처는 역사 자료·고증·참고문헌 메뉴 또는 사물 정보에서 제공하는 방향이다. 안내 문구와 UI는 미정이다.
- 새 시대·지형·생활·건축·복식·애니메이션·사건·군사/함선 등의 추가 콘텐츠를 묶은 독립 유료 DLC가 될 수 있다. `Tiny Days — Joseon / Imjin War`는 가제 예시다. 유료화·묶음·가격·순서·출시 일정은 확정하지 않는다.

### 6.6 출시 후 웹 체험판 후보

- Steam 본편 개발·출시를 우선한다. 웹게임으로 개발 방향을 전환하지 않는다.
- 출시 → 반응 확인 → 인기 시스템 분석 → 본편 자산 경량화 → 작은 웹 체험판 → Steam 유입이라는 순서를 후보로 둔다. 광고 수익보다 설치 없이 체험하는 홍보 수단을 목표로 검토한다.
- 작은 지역·농촌·주민 10~20명·생활 AI·낮밤·비·번개·손가락 개입·이름 붙이기·제한된 주민 관찰과 줌은 예시다. 본편에서 선호가 확인된 후 기능과 규모를 결정한다.
- 접속하면 세계가 바로 움직이고, 먼 산·마을·도로로 더 넓은 세계를 암시하며 Steam 본편으로 연결하는 방식을 검토한다. 실제 문구·이동 제한 방식은 미정이다.

### 6.7 우선순위와 추가 합의

- 세 축은 세계의 작은 반응을 관찰하는 개입, 한 주민에게 애착을 갖는 생애 관찰, 과거 생활을 바라보는 역사 디오라마다. 별도 스트리머 모드·시청자 참여·방송용 이벤트는 현재 확장 우선순위에 넣지 않는다.
- 각 후보를 무료 업데이트·유료 DLC·별도 체험판 중 어디에 포함할지, 제작 시점·최소 범위·기술 타당성·고증과 자산 확보·성능·저장 호환 정책은 착수 전 사용자와 합의한다.
- 이 기록만으로 본편 단계 추가·착수·완료나 캐릭터 보완 재개를 승인한 것으로 해석하지 않는다.

| 6. 출시 품질 검증 | 실제 실행 파일, 저장·창·음량·장시간 안정성·성능 | 합의한 목표 PC·창 크기·시간·성능 기준 통과, 실제 입력과 진행 중 복원 확인, 출시 사용자 확인 |

단계 통과 전 미검증과 사용자 확인 대기를 명시한다. 단계 진입 자체로 미정 내용을 확정하거나 다음 단계 구현을 자동 승인하지 않는다. 저장·성능 등 후반 품질 검증 항목이라도 앞선 설계에서 필요한 결정은 미루지 않는다.

### v0.16 현재 제작 기준 — 이전 순서보다 우선

- 현재 캐릭터 디자인과 애니메이션은 임시 작업물이다. 과장되고 사랑스럽고 귀여운 동작이라는 목표는 유지하지만 현재 결과가 그 목표를 달성했다고 기록하지 않는다.
- 현재 주민 이동 속도는 느리고 애니메이션은 사용자 만족 기준에 미달한다. 캐릭터의 기본 체형·얼굴·작업복·두 발·네 발 자세를 먼저 확인한 뒤, 실제 이동 속도와 발 디딤을 함께 조정하며 핵심 애니메이션을 재개한다.
- 농가의 문·문틀 정렬과 지붕의 두께·처마·접합부를 보완해 현재 집과 소품의 기본 품질을 높인다. 종류와 변형의 대량 확장은 핵심 게임플레이 검증 뒤에 진행한다.
- 2-6 피드백 반영은 자유 카메라를 먼저 적용하고, 여러 방향에서 농가·소품·캐릭터를 확인하는 순서로 진행한다.
- 2-2의 과거 확인은 당시 제작 기준에 대한 확인이며 출시 최종 외형 승인이 아니다. 2-3 추가 동작·보완, 2-4 갈퀴·수레 연출, 2-5 곰·여우 제작은 보류한다. 보류한 작업은 완료 처리하지 않는다.
- 단계 번호를 유지하고 2-6 농가·임시 생활 장면을 먼저 제작한다. 앞 단계 사용자 확인 이후 다음 단계로 진행한다는 기존 순서의 이번 합의된 예외다.
- 맑은 봄 낮, 뒤쪽 집 2채·창고, 앞쪽 밭, 옆쪽 쉼터와 완만한 흙길·울타리·나무·벤치·생활 소품을 구성한다. 참고 이미지의 빛·색·단순한 입체 형태·밀도를 농경세계에 맞춘다.
- 기존 토끼 6명을 임시 배치한다. 토끼·곰·여우라는 향후 종 구성이나 본게임 시작 인구를 변경하지 않는다. 기존 이동·대기를 사용해 장소 사이 이동과 머무르기를 시차를 두고 연출한다. 작업 장소의 대기는 임시 표현이며 새 작업 애니메이션·실제 생산·자원·피로 판단을 만들지 않는다.
- 주민 위치·활동 진행과 외형·동작 재생을 분리한다. 기존 원본·동작·검토 장면과 수동 영역을 보존하고 별도 농가 장면을 만든다.
- 고정 비교 구도와 가까운·전체 보기만 검토용으로 제공한다. 자유 카메라 키·제한은 2-7 착수 전 합의한다.
- 컴파일·독립 재생·수동 영역 보존 자동 검사와 실제 Game 창의 이동·겹침·관통·가독성·5분 관찰을 구분한다. 사용자 확인 대상은 농가 구성과 임시 생활 밀도이며 최종 캐릭터 품질 승인이 아니다.
- 농가 장면 사용자 확인 후 2-7을 구체화하고 이후 3단계 자율 생활 기반으로 이어간다. 캐릭터 보완 재개 시점은 별도 합의한다.

### 2단계 세부 계획 — 대표 화면과 생활 검증

**목표: 안정된 작은 농가에서 주민의 외형과 행동이 귀엽고, 계속 지켜보고 싶은지 확인한다.**

2-1 제작 준비와 2-2 외형, 2-3 기본 이동의 사용자 확인을 마쳤다. 두 번째 검토인 자세 전환·출발·정지와 연결 장면을 제작하고 자동 검사와 실제 Game 창 확인을 수행했다. 이후 크고 만화적인 탄력으로 기본 이동과 전환을 함께 보완하기로 합의했다. v0.15에서 캐릭터 보완을 보류하고 2-6을 선행한다. 아래 2-3~2-5 상세 내용은 재개 시 참고할 기존 계획이다.

#### 2-1 확정 제작 기반과 자산 순서

- Unity 2022.3.20f1 + 설치에 포함된 URP 14.0.10의 3D Universal Renderer + Blender 5.2.1을 사용한다. 패키지 의존성은 manifest와 lock 파일로 기록한다.
- Blender에서 관절 모델·동작 클립을 제작하고 FBX로 명시적 출력하여 Unity Generic으로 가져온다. 실제 위치 이동은 Unity가 제어하며 자동 루트 이동은 사용하지 않는다.
- 기존 모델은 배치·크기 시험용 복사본에만 활용한다. 본게임 주민·시설·자연·소품의 최종 외형은 새로 만든다. 기존 팔·다리 흔들기 코드를 새 주민 동작 기반으로 사용하지 않는다.
- 카메라·식물·조명 등의 필요한 로직과 생성/수동 영역 분리·반복 검증 구조만 선별 검토한다. 프로토타입의 판단·생산·저장은 3단계 이후 후보로 남긴다.
- 원본은 Assets 밖 ArtSource, 생성 스크립트는 Tools, 자동 출력은 Assets/Art/Generated, 수동 자산은 Assets/Art/Manual로 구분한다. 장면의 GeneratedReview와 ManualEdits를 분리해 반복 생성이 수동 영역을 덮어쓰지 않게 한다.
- 2-2 토끼 모델·작업복·관절·기본 자세 → 2-3 보행/전환 → 2-4 작은 나무 갈퀴·손수레·소품 연출 → 2-5 곰·여우 → 2-6 농가 자산 → 2-7 하루의 빛·관찰 순서로 제작한다.
- 완만한 흙길을 중심으로 뒤쪽 집·창고, 앞쪽 밭, 옆쪽 쉼터를 연결한다. 카메라가 회전하므로 모든 방향의 외형과 가독성을 확인한다.
- 2-2에서는 정해진 비교 구도를 사용한다. 본게임 카메라 조작 키·회전/높이/확대 제한은 구현 전 합의 대상으로 유지한다.

#### 2-3 이동·자세 전환 — 합의한 제작 계획

현재 외형을 기준으로 빈손 토끼 한 명의 연출용 장면을 만든다. 외형 재디자인 없이 동작에 필요한 관절·변형만 보완한다. 실제 위치 이동은 Unity가 담당하고 Blender Generic 클립의 발 접지 구간과 이동량을 맞춘다.

| 검토 순서 | 제작할 동작 | 확인 후 진행 |
|---|---|---|
| 첫 검토: 기본 이동 | 두 발·네 발 대기: 호흡과 귀 움직임. 두 발 걷기: 좌우 발을 번갈아 쓰고 짧은 공중 구간이 있는 총총걸음. 네 발 이동: 낮은 준비·뒷발 밀기·착지 반동이 분명한 깡충 이동 | 사용자 기본 이동 확인 후 두 번째 검토 착수 |
| 두 번째 검토: 자세 전환 | 멈춤→몸 낮춤→앞발 받침→뒷다리 접기. 반대로 뒷발로 중심 이동→앞발 떼기→일어서기. 이동 시작·정지 연결 | 사용자 전환 확인 후 특별 행동 착수 |
| 세 번째 검토: 특별 행동 | 신남: 귀 세우기→준비→네 발로 짧게 연속 뛰기→진정. 호기심: 귀 세우고 고개 기울이기→낮게 접근→작은 돌 살피기→두 발 복귀 | 사용자 종합 확인 후 2-3 완료 및 2-4 착수 |

- 특별 행동은 작지만 분명한 몸짓이다. 높이 뛰기·몸 비틀기·대상 주변 돌기는 첫 초안에서 제외한다. 시선·표정 동작은 이번 범위가 아니다.
- 보폭·속도·동작 길이는 검토용 값이며 본게임 밸런스·발생 확률로 확정하지 않는다. 자율 판단은 3단계에서 연결한다.
- 기존 정지 외형 장면을 보존하고 별도 동작 장면에서 선택·재생/일시정지·다시 재생·느린 재생·고정 비교 구도를 제공한다. 본게임 UI·배속·카메라 조작을 확정하는 도구가 아니다.
- Blender→Unity 동작·방향·크기·재질·관절 연결, 접지·착지·미끄러짐·관통·관절 틈·반복 경계와 수동 영역 보존을 검사한다. 정면·측면·후면·비스듬한 구도 및 가까운/축소 화면을 확인한다.
- 실제 Unity Game 창 Play 모드에서 개별 동작과 검토 조작을 확인한다. 이후 검토에서는 연결 동작도 확인한다. 자동 검사·실제 관찰·사용자 확인을 따로 기록한다.

#### 2-3 두 번째 검토 — 자세 전환·이동 연결

- v0.13의 기본 이동은 사용자 확인을 마쳤으나, v0.14에서 기본 이동·전환 모두 탄력을 키우기로 합의했다. 외형은 유지하며 수정 동작은 사용자 재확인 대상으로 둔다.
- 두 발→네 발: 멈춤→몸 낮춤→앞발 받침→뒷다리 접기. 네 발→두 발: 뒷발로 중심 이동→앞발 떼기→일어서기. 발 위치를 바꾸면 들어 옮긴다. 착지에 엉덩이 반동을 넣고 귀·머리·꼬리는 몸보다 늦게 따라와 잦아든다.
- 걷기와 깡충 이동 각각의 출발·정지를 추가한다. 걷기는 중심 이동과 첫걸음, 마지막 디딤으로 연결하고 깡충 이동은 낮은 준비와 뒷발 밀기, 마지막 착지와 안정으로 연결한다.
- 첫 검토값은 내려가기 1.2초·일어서기 1.4초, 출발·정지 각각 약 0.6초다. 접촉 시점에 맞춰 조정하며 본게임 확정 속도로 기록하지 않는다.
- Blender/Generic을 유지한다. 반복/단발 클립을 구분하고 Unity가 클립별 누적 이동량을 사용해 현재 위치를 이어받는다. 자세 전환 후에는 해당 대기로 연결한다.
- 연결 장면: 두 발 대기→출발·걷기·정지→네 발 전환→네 발 대기→출발·깡충 이동·정지→두 발 전환→대기. 한 번 재생 후 마지막 대기를 유지한다.
- 일시정지·재개·처음부터·느린 재생·구도/크기 선택을 유지한다. 개별 클립 선택의 시작 자세 초기화와 연결 장면의 자연스러운 전환은 구분한다.
- 기존 기본 이동 비교 자료를 보존한다. 접지·관통·관절 변형·연결 경계·누적 이동·반복/단발 처리·가져오기·수동 영역을 검사하고 실제 Game 창에서 정상/느린 연결 재생 및 전환 도중 정지·재개·초기화를 확인한다.
- v0.14 보완 결과는 탄력 동작 사용자 확인 대기로 남긴다. 신남·호기심은 이번 결과 사용자 확인 후 제작하며 2-3 전체 완료로 미리 기록하지 않는다.

#### 2-3 탄력 동작 보완 — v0.14 합의

- 작고 절제된 움직임보다 크고 만화적인 준비·도약·착지 반동을 채택한다. 외형을 늘이거나 새로 디자인하지 않고 몸의 자세·타이밍으로 표현한다.
- 기존 10클립을 보완한다. 총총걸음은 좌우 발을 번갈아 쓰며 짧게 두 발 모두 뜬다. 네 발 이동은 낮은 준비, 뒷발 밀기와 착지를 강조한다. 대기는 계속 뛰거나 들썩이지 않게 한다.
- 두 발→네 발은 앞발 접촉 후 몸이 낮아지고 엉덩이가 솟았다 안정된다. 네 발→두 발은 뒷발 지지와 일어서기를 연결하고 마지막 디딤에 무릎·엉덩이가 탄력 있게 반응한다. 양방향을 단순 역재생하지 않고 각각 조정한다.
- 출발·정지와 머리·귀·꼬리의 늦게 따라오는 움직임을 연결한다. 현재 속도·이동량·클립 길이를 초안 기준으로 유지하며 본게임 수치로 확정하지 않는다.
- 이전 원본·동작·비교 자료는 BeforeElasticRevision에 보존한다. 이전 동작과 자세가 같아야 한다는 검사는 교체하고 외형 원본 보존·접지·공중 구간·가져오기·연결·수동 영역을 확인한다.
- 정상/느린 연결 재생, 전환 중 정지·재개·초기화와 네 방향·가까운/축소 구도를 실제 Game 창에서 확인한다. 결과는 **2-3 탄력 동작 사용자 확인 대기**로 남긴다. 신남·호기심은 그 이후다.

#### 2-4 첫 검증 장면

- **도구 운반:** 작은 나무 갈퀴를 두 발로 들고 이동 → 멈춰 내려놓기 → 네 발 자세로 바꾸기 → 손잡이를 입으로 물고 짧게 이동 → 내려놓고 두 발로 돌아와 다시 들기.
- **수레 소동:** 두 발로 끌기 → 자세를 바꾸다 놓치기 → 수레가 조금 굴러감 → 잠깐 바라보기 → 다가가 두 발로 다시 잡고 이어가기.

빈손 야외 이동 외에 작업·운반 중에도 네 발 전환을 허용하는 방향이다. 실제 경로 오류·물건 유실·영구 정체와 의도된 연출을 구분한다. 수레를 입이나 목·어깨의 끈으로 끄는 방식은 이번 첫 검증에 포함하지 않고 아이디어로 보존한다.

#### 2단계 확인 방법

- 캐릭터 가까이 보기와 마을 전체 보기에서 각각 외형·동작을 확인한다.
- 실제 Unity Game 창에서 자세 전환·소품 전달·수레 회수·카메라 조작을 확인한다.
- 좌우 360도 회전, 상하 회전, 높낮이·평면 이동과 확대/축소를 각각 및 조합해 확인한다. 기본 구도 복귀는 위치·회전·높이·확대 상태를 함께 되돌리는지 확인한다.
- 여러 방향과 높은·낮은 시점에서 주민·건물·소품이 자연스럽게 보이는지 확인한다. 합의한 조작 범위에서 지면 아래 진입·화면 뒤집힘이 없고, 화면 비율을 바꿔도 조작과 기본 구도 복귀가 동작하는지 확인한다.
- 종합 장면은 실제 시간으로 **5분 관찰**해 반복감과 행동 밀도를 확인한다. 본게임 장시간 안정성 검증과 구분한다.
- 작은 창과 가로·세로 비율에서 확인한다. 출시 최소 해상도와 성능 목표는 별도 합의한다.
- 구현·자동 검사·실제 관찰·사용자 확인을 따로 기록한다. 외형과 연출은 사용자 확인 없이 통과로 처리하지 않는다.

### 주요 검증 상황

- 무입력 상태에서 주민의 일·휴식·생활 순환과 회복이 이어지는가.
- 확장 제안을 무시해도 현재 영역에서 정상 생활과 가능한 질적 성장이 이어지는가.
- 식량·공간 부족이 영구 정체나 붕괴를 만들지 않는가.
- 장식과 건설 후보지가 겹치거나 통행이 어려워질 때 합의한 보존·복구 규칙을 지키는가.
- 계절·날씨 전환이 화면과 행동·생산에 반영되며 급격한 오류를 만들지 않는가.
- 이동·운반·건설 중 저장 후 복원할 때 중복 생산·예약 유실·진행 소실이 없는가.
- 보존 모드·일시정지·배속 전환이 합의한 생활·시간 규칙을 지키는가.
- 실제 창의 버튼·음량·크기 변경과 재실행 후 설정 유지가 정상인가.
- 실제 목표 환경의 장시간 관찰과 성능 측정이 합의 기준을 통과하는가.

## 9. 프로토타입 재사용 후보와 남은 검증

기존 코드는 **재사용 후보이며 본게임 규모에서 검증된 완성 기반이 아니다.**

| 후보 | 본게임에서 확인할 점 |
|---|---|
| 자율 생활·개인차 | 여러 종·직업·환경 반응과 본게임 규모에서 판단이 유지되는지 |
| 이동·충돌 회피·예약·실패 복구 | 변경되는 지형·건물·장식과 늘어난 주민에 대응하는지 |
| 작물→수확→운반→저장→소비 | 다종 자원과 계절 영향을 연결할 수 있는지 |
| 헛간 자율 건설 | 반복되는 건설·부지 선택·확장과 꾸미기 관계로 확장 가능한지 |
| 카메라·낮밤·식물·연기 | 기존 이동·확대 로직을 검토하되 좌우·상하 회전, 높낮이 이동, 기본 구도 복귀까지 확장 필요. 여러 시점·자유로운 창 비율에서 품질과 가독성 재검증 |
| 일시정지·배속·HUD | 본게임 UI·성능 목표에 맞는지. 1×~16×는 본게임 확정 범위가 아님 |
| 로컬 JSON 저장 | 여러 주민·시설·환경의 ID·예약·진행을 안전하게 복원하는지 |
| Blender 원본·생성기·Unity 생성/검증 | 수동 자산을 보존하며 본게임 제작에 재사용 가능한지 |

토끼 모델, 주민 6명, 고정 지형, 단일 작물·식량, 헛간 1회와 모든 성장·자원·건설 수치는 프로토타입 한정이다. 실제 환경음 음원은 없고 음량 제어 구조만 있다. Built-in 렌더링 등 프로토타입의 기술 선택을 본게임 확정값으로 자동 승계하지 않는다.

### 프로토타입 상태 — 2026-09-14 최신 기록 기준

- 총 6단계이며 **6단계는 진행 중**이다. 1~5단계의 구현·자동 검사와 사용자 시각 확인을 구분한다.
