# Tiny Days 본게임 마스터 플랜 v0.15

작성일: 2026-09-14  
최종 갱신: 2026-09-15  
상태: **캐릭터 디자인·애니메이션 임시 사용 / 2-3·2-4·2-5 보완 보류 / 2-6 농가·임시 생활 장면 사용자 확인 대기**  
기준: 기존 게임 기획서 v0.3 + 사용자와 합의한 본게임 방향 및 통합 계획

## 1. 문서의 역할과 운영 원칙

이 문서는 Tiny Days 본게임의 작업 기준이다. 매 작업 전에 읽고 현재 범위, 미정 사항, 통과 기준을 확인한다. 프로토타입의 마스터 플랜과 단계 번호는 별개다.

큰 구분은 **1~6단계**, 세부 구분은 **2-1, 2-2…**로 표기한다. 이 문서의 절 번호와 제작 단계 번호는 구분한다.

- **확정 방향:** 게임의 정체성과 판단 원칙. 변경은 사용자와 합의한다.
- **1.0 범위:** 채택한 기능의 범위이며, 구현 완료를 의미하지 않는다. 세부 수치와 목록은 별도 합의한다.
- **장기 후보:** 비전을 보존하기 위한 목록이다. 구현 승인이나 출시 약속이 아니다.
- **미정 사항:** 관련 기능 착수 전 합의가 필요하다. 예시·후보·프로토타입 값을 확정값으로 사용하지 않는다.
- 새 요청이 현재 기준을 바꾸면 충돌 내용을 알리고 합의한 내용을 이 문서에 반영한 뒤 작업한다.
- 작업 결과, 남은 검증과 사용자 확인 상태를 이 문서에 갱신한다. 과거 기록과 최신 기록이 충돌하고 근거가 불분명하면 사용자에게 확인한다.
- 기존 수동 자산과 변경 사항을 보존한다. Unity 2022.3.20f1 / Blender 5.2.1을 임의로 업그레이드하지 않는다.
- 문서와 참고 이미지는 Git 관리 대상으로 유지한다. 다른 PC로 이전할 때 최신 코드·기획·필요 자산이 실제 커밋·푸시되었는지 확인한다. 파일 생성만으로 커밋·푸시 완료라고 보고하지 않는다.

작업 요청은 먼저 이해한 내용을 요약하고 승인 후 수정한다. 이미 합의한 계획의 실행 요청은 바로 진행한다. 사용자가 요청하기 전에는 수정 디테일을 나열하지 않고, 작업 후에는 **작업 / 확인 / 다음**으로 간결하게 보고하며 다음 작업의 권장 모델과 플랜 모드 여부를 안내한다.

## 2. 게임 목표와 정체성 — 확정 방향

**귀여운 동물 주민이 스스로 생활하고 발전하는 모습을, 화면 한켠에서 편안하게 지켜보는 작은 디오라마 게임.**

가제는 Tiny Days. 장르는 힐링형 방치 시뮬레이션·생활 관찰·마을 성장 시뮬레이션이다. Windows / Steam을 우선하며 약 1달러 수준의 저가 출시를 목표로 한다. 정확한 판매가는 추후 결정한다. 개발 환경은 Unity + Blender + Codex다.

### 경험 목표

| 시점 | 목표 경험 |
|---|---|
| 처음 10분 | 예쁘다. 귀엽다. |
| 약 30분 | 화면 한켠에 계속 켜두고 싶다. |
| 며칠 뒤 | 이전보다 생활과 풍경이 조금 달라졌다. |

콘텐츠 양보다 가격이 아깝지 않은 시각적 매력, 안정적인 생활, 천천히 축적되는 변화를 우선한다. 며칠 뒤의 변화는 1.0에서 실제 실행한 시간 동안 누적된 변화다.

### 디자인 원칙

1. 실행해 두는 것 자체가 즐거울 만큼 예쁘고 편안해야 한다.
2. 주민은 환경·자원·계절·날씨·성격·필요를 바탕으로 스스로 생활한다.
3. 플레이어에게 필수 퀘스트나 반복 과제를 요구하지 않는다. 원할 때 방향을 제시하고 꾸민다.
4. 지형 배치·날씨·주민·작은 사건의 조합으로 매번 조금씩 다른 일상을 만든다.
5. 레벨 숫자보다 생활과 풍경의 변화로 발전을 표현한다.
6. 농땡이·감상·실수·놀이 등 비효율적인 행동도 주요 콘텐츠다. 큰 손해를 강요하지 않는다.
7. 성장할수록 면적과 생산량뿐 아니라 여가와 생활의 질이 풍요로워진다.

새 기능은 마을을 더 예쁘고 살아 있게 만드는지, 새로운 생활 장면을 만드는지, 기존 시스템과 결합하는지, 불필요한 숙제를 만들지 않는지로 판단한다.

## 3. 세계와 1.0 성장 범위

1.0은 마법 없는 가상의 저기술 농경세계다. 특정 시대의 중세 유럽을 정확히 재현하기보다 따뜻하고 담백한 농촌 생활을 표현한다.

**채집 → 초기 정착 → 농경 → 안정된 농가 → 부농 → 작은 농촌마을**

첫 출시는 한 마을의 생활을 깊게 만드는 데 집중한다. 주변 어둠 속 땅을 조금씩 밝혀 영역을 넓힐 수 있지만 여러 독립 마을을 운영하는 기능은 장기 후보다. 고정 레벨 상승이나 강제 엔딩 대신 생활 안정과 성숙을 지향하며, 성숙의 구체적 조건과 1.0 규모는 미정이다.

## 4. 1.0 확정 범위와 행동 원칙

### 4.1 플레이어 개입과 자율 건설

- 시작할 때 마을의 큰 성장 방향을 선택하고 이후 바꿀 수 있다. 변화는 서서히 생활에 반영된다. 방향 선택지 목록은 미정이다.
- 주민 직접 명령을 기본 진행 방식으로 삼지 않는다.
- 플레이어는 장식을 배치하고 건물 외형을 변경한다. 건물 위치를 직접 지정하거나 완공된 건물을 재배치하는 기능은 현재 확정 범위에 포함하지 않는다.
- 주민이 필요와 주변 상황을 보고 건설과 위치를 결정한다. 기존 장식을 보존할 수 있는 위치를 찾고, 적합한 공간이 없으면 건설을 보류하고 알린다.
- 장식 편집의 접근성·통행 규칙과 알림 방식은 착수 전에 합의한다.

### 4.2 시작 지형과 주변 확장

- 전체 세계를 처음부터 공개하지 않고 정착지 주변만 보여준다.
- 검증된 농경 지형 틀 안에서 자연·자원 배치를 달리한다. 틀의 종류·생성 방식·자원 분포 규칙은 미정이다.
- 주민이 주변 땅 확장을 제안하면 플레이어가 열 방향을 선택한다.
- 응답이 없으면 땅 확장은 기다리되 현재 영역에서 생활과 가능한 질적 성장은 계속된다. 선택 대기를 마을 전체 정지나 필수 과제로 만들지 않는다.
- 어둠은 미공개 영역을 표현하는 방향이며 마법 세계관을 뜻하지 않는다. 탐색 연출·확장 조건·비용·한계는 미정이다.

### 4.3 주민·성격·생활

- 여러 종류의 담백한 의인화 동물을 사용한다. 종과 성격·직업은 독립적이다.
- 주민은 생산 유닛이 아니라 관찰과 애착의 중심이다. 성향·취향·현재 상태와 환경에 따라 다른 행동을 한다.
- 작은 교류, 좋아하는 장소, 감상과 여가, 가벼운 실수와 생활 소동을 포함한다.
- 후보 장면: 인사, 함께 쉬기, 일몰 감상, 처마 아래 비 구경, 낮잠, 물건을 떨어뜨렸다 줍기. 예시는 최종 행동 목록이 아니다.
- 의도한 생활 소동과 이동·예약 오류를 구분한다. 영구 정체나 경로 실패를 귀여운 실수로 정당화하지 않는다.
- 2단계 대표 주민은 토끼·곰·여우다. 본게임 전체 종·직업·성격 목록과 특성 개수, 행동 빈도는 미정이다. v0.3의 성격 2~3개도 최종 수치로 확정하지 않는다.
- 두 발 생활을 기본으로 하며 신남·호기심 같은 특별한 순간에 네 발 움직임을 사용하고, 평소에도 가끔 섞는다. 작업·운반 중의 자세 전환도 귀여운 생활 연출로 활용한다.
- 물건을 내려놓고 다시 집는 과정까지 보여줘 자세와 소품의 관계를 자연스럽게 연결한다. 소동은 잠깐의 변화 뒤 스스로 수습한다.
- 먼저 토끼로 두 발·네 발 전환을 검증하고 곰·여우는 체형과 움직임에 맞춰 별도로 확인한다. 발생 빈도와 종별 행동 목록은 장면 비교 후 합의하며, 최종 자율 행동 확률은 아직 정하지 않는다.
- 아이·가족·출산·노화·세대교체·확장된 관계는 1.0에서 제외하고 후속 후보로 둔다.

### 4.4 생산·부족·자율 발전

- 채집·농경·운반·저장·소비를 생활 행동과 연결한다.
- 소규모 가축의 간단한 돌봄과 생활 반응을 포함한다. 종·생산물·수량은 별도로 합의한다.
- 자원·시설·환경·주민·선택한 방향을 바탕으로 필요한 생산과 건설이 일어난다.
- 예시 흐름: 식량 부족 → 채집·농경 증가 → 생산 회복 → 저장 필요 증가 → 저장시설 확대. 정확한 조건과 수치는 미정이다.
- 부족하면 성장이 느려지고 주민이 적응·회복한다. 굶주림에 따른 사망이나 마을 붕괴는 없다.
- 전쟁·범죄·잔혹한 사건·심각한 싸움·강한 경쟁은 1.0에서 제외한다.
- 정원·쉼터·생활 공간과 여가가 늘어나는 질적 성장을 포함한다. 구체적 시설 목록과 해금 조건은 미정이다.
- 최초의 집·오래된 나무 같은 마을의 흔적을 남기는 방향을 유지한다. 보존 대상과 재건축·꾸미기와의 관계는 별도 합의한다.

### 4.5 시간·계절·날씨

- 새벽·아침·낮·오후·일몰·밤의 빛과 생활 변화를 표현한다.
- 사계절을 적용하고 생활과 생산에도 영향을 준다. 봄의 파종, 가을의 수확, 겨울의 실내 활동 등은 구체화할 예시다.
- 기본 날씨는 **맑음·흐림·비·눈**이다. 강한 비·안개·독립적인 바람 상태·한파·더위·가뭄 등 추가 날씨는 후속 후보로 둔다. 풍경의 작물 흔들림은 별개다.
- 날씨에 대한 행동 반응을 포함한다. 물웅덩이·적설·발자국처럼 오래 남는 흔적의 종류와 구현 범위는 미정이다.
- 일시정지와 시간 배속을 지원한다. 하루·계절 길이, 배속 범위·정확한 속도는 미정이다.
- **1.0은 게임 실행 중에만 진행한다.** 종료 중 진행은 포함하지 않는다.

### 4.6 성장 설정

| 설정 | 의도 |
|---|---|
| 자율 성장 | 선택한 방향에 따라 생활과 발전을 이어간다. |
| 보존 모드 | 전체적인 풍경과 규모를 유지하면서 생활은 이어간다. |
| 일시정지 | 시간을 멈춘다. |

보존 모드에서 허용할 건설·재배·장식·계절 변화와 전환 방식은 구현 전에 합의한다. 완만한 성장의 별도 모드는 후속 검토 대상으로 둔다.

### 4.7 UI·창·정보

- 화면 한켠에 계속 켜두기 좋은 최소 UI와 넓은 마을 화면을 지향한다.
- 카메라는 좌우 360도 회전, 상하 회전, 높낮이 이동, 평면 이동, 확대/축소와 기본 구도 복귀를 지원한다. 높낮이 이동은 상하 회전·확대와 별도의 조작으로 제공한다.
- 비스듬히 내려다보는 미니어처 구도를 기본으로 하되 고정하지 않는다. 상하 회전과 높낮이는 지면 아래 진입이나 화면 뒤집힘을 막는 범위에서 조절한다. 구체적인 조작 키·각도·높이·확대 범위와 건물 접근 처리는 구현 전에 합의한다.
- 자유로운 창 크기와 가로세로 비율에 대응한다. 지원 최소 크기와 구도 처리 방식은 미정이다.
- 필요한 정보는 요청했을 때 표시하고, 자원은 과도한 숫자보다 ‘식량: 넉넉함’ 같은 생활 상태 표현을 우선한다.
- 데스크톱 모드·항상 위·입력 무시·창 위치와 크기 저장의 세부 범위는 후속 검토한다.

### 4.8 사운드·저장·실행 품질

- 환경음을 중요한 힐링 요소로 취급한다. 바람·새·물·비·가축·생활 작업음 등은 음원 구성 후보다.
- 전체 사운드·BGM·효과음 켜기/끄기, BGM·효과음 개별 볼륨과 재실행 후 설정 유지를 제공한다.
- BGM을 끄고 환경음을 들을 수 있는 구성을 검토한다. 환경음 별도 채널·볼륨 여부, 기본값·음원 확보 방식은 미정이다.
- 안정적인 저장·불러오기와 진행 상태 복원을 제공한다. 형식·저장 시점·백업·호환 정책은 구현 전에 합의한다.
- 실제 Windows 실행 파일에서 입력, 창 크기 변경, 장시간 실행, 주민 정체 복구, 사운드 설정 유지를 검증한다.

- 단계 번호를 유지하고 2-6 농가·임시 생활 장면을 먼저 제작한다. 앞 단계 사용자 확인 이후 다음 단계로 진행한다는 기존 순서의 이번 합의된 예외다.

- 주민 위치·활동 진행과 외형·동작 재생을 분리한다. 기존 원본·동작·검토 장면과 수동 영역을 보존하고 별도 농가 장면을 만든다.
- 고정 비교 구도와 가까운·전체 보기만 검토용으로 제공한다. 자유 카메라 키·제한은 2-7 착수 전 합의한다.
- 컴파일·독립 재생·수동 영역 보존 자동 검사와 실제 Game 창의 이동·겹침·관통·가독성·5분 관찰을 구분한다. 사용자 확인 대상은 농가 구성과 임시 생활 밀도이며 최종 캐릭터 품질 승인이 아니다.
- 농가 장면 사용자 확인 후 2-7을 구체화하고 이후 3단계 자율 생활 기반으로 이어간다. 캐릭터 보완 재개 시점은 별도 합의한다.

### 2단계 세부 계획 — 대표 화면과 생활 검증

**목표: 안정된 작은 농가에서 주민의 외형과 행동이 귀엽고, 계속 지켜보고 싶은지 확인한다.**

2-1 제작 준비와 2-2 외형, 2-3 기본 이동의 사용자 확인을 마쳤다. 두 번째 검토인 자세 전환·출발·정지와 연결 장면을 제작하고 자동 검사와 실제 Game 창 확인을 수행했다. 이후 크고 만화적인 탄력으로 기본 이동과 전환을 함께 보완하기로 합의했다. v0.15에서 캐릭터 보완을 보류하고 2-6을 선행한다. 아래 2-3~2-5 상세 내용은 재개 시 참고할 기존 계획이다.

#### 2-1 확정 제작 기반과 자산 순서

- Unity 2022.3.20f1 + 설치에 포함된 URP 14.0.10의 3D Universal Renderer + Blender 5.2.1을 사용한다. 패키지 의존성은 manifest와 lock 파일로 기록한다.
- Blender에서 관절 모델·동작 클립을 제작하고 FBX로 명시적 출력하여 Unity Generic으로 가져온다. 실제 위치 이동은 Unity가 제어하며 자동 루트 이동은 사용하지 않는다.
- 기존 모델은 배치·크기 시험용 복사본에만 활용한다. 본게임 주민·시설·자연·소품의 최종 외형은 새로 만든다. 기존 팔·다리 흔들기 코드를 새 주민 동작 기반으로 사용하지 않는다.
- 카메라·식물·조명 등의 필요한 로직과 생성/수동 영역 분리·반복 검증 구조만 선별 검토한다. 프로토타입의 판단·생산·저장은 3단계 이후 후보로 남긴다.
- 원본은 Assets 밖 ArtSource, 생성 스크립트는 Tools, 자동 출력은 Assets/Art/Generated, 수동 자산은 Assets/Art/Manual로 구분한다. 장면의 GeneratedReview와 ManualEdits를 분리해 반복 생성이 수동 영역을 덮어쓰지 않게 한다.
- 2-2 토끼 모델·작업복·관절·기본 자세 → 2-3 보행/전환 → 2-4 작은 나무 갈퀴·손수레·소품 연출 → 2-5 곰·여우 → 2-6 농가 자산 → 2-7 하루의 빛·관찰 순서로 제작한다.
- 완만한 흙길을 중심으로 뒤쪽 집·창고, 앞쪽 밭, 옆쪽 쉼터를 연결한다. 카메라가 회전하므로 모든 방향의 외형과 가독성을 확인한다.
- 2-2에서는 정해진 비교 구도를 사용한다. 본게임 카메라 조작 키·회전/높이/확대 제한은 구현 전 합의 대상으로 유지한다.

#### 2-3 이동·자세 전환 — 합의한 제작 계획

현재 외형을 기준으로 빈손 토끼 한 명의 연출용 장면을 만든다. 외형 재디자인 없이 동작에 필요한 관절·변형만 보완한다. 실제 위치 이동은 Unity가 담당하고 Blender Generic 클립의 발 접지 구간과 이동량을 맞춘다.

| 검토 순서 | 제작할 동작 | 확인 후 진행 |
|---|---|---|
| 첫 검토: 기본 이동 | 두 발·네 발 대기: 호흡과 귀 움직임. 두 발 걷기: 좌우 발을 번갈아 쓰고 짧은 공중 구간이 있는 총총걸음. 네 발 이동: 낮은 준비·뒷발 밀기·착지 반동이 분명한 깡충 이동 | 사용자 기본 이동 확인 후 두 번째 검토 착수 |
| 두 번째 검토: 자세 전환 | 멈춤→몸 낮춤→앞발 받침→뒷다리 접기. 반대로 뒷발로 중심 이동→앞발 떼기→일어서기. 이동 시작·정지 연결 | 사용자 전환 확인 후 특별 행동 착수 |
| 세 번째 검토: 특별 행동 | 신남: 귀 세우기→준비→네 발로 짧게 연속 뛰기→진정. 호기심: 귀 세우고 고개 기울이기→낮게 접근→작은 돌 살피기→두 발 복귀 | 사용자 종합 확인 후 2-3 완료 및 2-4 착수 |

- 특별 행동은 작지만 분명한 몸짓이다. 높이 뛰기·몸 비틀기·대상 주변 돌기는 첫 초안에서 제외한다. 시선·표정 동작은 이번 범위가 아니다.
- 보폭·속도·동작 길이는 검토용 값이며 본게임 밸런스·발생 확률로 확정하지 않는다. 자율 판단은 3단계에서 연결한다.
- 기존 정지 외형 장면을 보존하고 별도 동작 장면에서 선택·재생/일시정지·다시 재생·느린 재생·고정 비교 구도를 제공한다. 본게임 UI·배속·카메라 조작을 확정하는 도구가 아니다.
- Blender→Unity 동작·방향·크기·재질·관절 연결, 접지·착지·미끄러짐·관통·관절 틈·반복 경계와 수동 영역 보존을 검사한다. 정면·측면·후면·비스듬한 구도 및 가까운/축소 화면을 확인한다.
- 실제 Unity Game 창 Play 모드에서 개별 동작과 검토 조작을 확인한다. 이후 검토에서는 연결 동작도 확인한다. 자동 검사·실제 관찰·사용자 확인을 따로 기록한다.

#### 2-3 두 번째 검토 — 자세 전환·이동 연결

- v0.13의 기본 이동은 사용자 확인을 마쳤으나, v0.14에서 기본 이동·전환 모두 탄력을 키우기로 합의했다. 외형은 유지하며 수정 동작은 사용자 재확인 대상으로 둔다.
- 두 발→네 발: 멈춤→몸 낮춤→앞발 받침→뒷다리 접기. 네 발→두 발: 뒷발로 중심 이동→앞발 떼기→일어서기. 발 위치를 바꾸면 들어 옮긴다. 착지에 엉덩이 반동을 넣고 귀·머리·꼬리는 몸보다 늦게 따라와 잦아든다.
- 걷기와 깡충 이동 각각의 출발·정지를 추가한다. 걷기는 중심 이동과 첫걸음, 마지막 디딤으로 연결하고 깡충 이동은 낮은 준비와 뒷발 밀기, 마지막 착지와 안정으로 연결한다.
- 첫 검토값은 내려가기 1.2초·일어서기 1.4초, 출발·정지 각각 약 0.6초다. 접촉 시점에 맞춰 조정하며 본게임 확정 속도로 기록하지 않는다.
- Blender/Generic을 유지한다. 반복/단발 클립을 구분하고 Unity가 클립별 누적 이동량을 사용해 현재 위치를 이어받는다. 자세 전환 후에는 해당 대기로 연결한다.
- 연결 장면: 두 발 대기→출발·걷기·정지→네 발 전환→네 발 대기→출발·깡충 이동·정지→두 발 전환→대기. 한 번 재생 후 마지막 대기를 유지한다.
- 일시정지·재개·처음부터·느린 재생·구도/크기 선택을 유지한다. 개별 클립 선택의 시작 자세 초기화와 연결 장면의 자연스러운 전환은 구분한다.
- 기존 기본 이동 비교 자료를 보존한다. 접지·관통·관절 변형·연결 경계·누적 이동·반복/단발 처리·가져오기·수동 영역을 검사하고 실제 Game 창에서 정상/느린 연결 재생 및 전환 도중 정지·재개·초기화를 확인한다.
- v0.14 보완 결과는 탄력 동작 사용자 확인 대기로 남긴다. 신남·호기심은 이번 결과 사용자 확인 후 제작하며 2-3 전체 완료로 미리 기록하지 않는다.

#### 2-3 탄력 동작 보완 — v0.14 합의

- 작고 절제된 움직임보다 크고 만화적인 준비·도약·착지 반동을 채택한다. 외형을 늘이거나 새로 디자인하지 않고 몸의 자세·타이밍으로 표현한다.
- 기존 10클립을 보완한다. 총총걸음은 좌우 발을 번갈아 쓰며 짧게 두 발 모두 뜬다. 네 발 이동은 낮은 준비, 뒷발 밀기와 착지를 강조한다. 대기는 계속 뛰거나 들썩이지 않게 한다.
- 두 발→네 발은 앞발 접촉 후 몸이 낮아지고 엉덩이가 솟았다 안정된다. 네 발→두 발은 뒷발 지지와 일어서기를 연결하고 마지막 디딤에 무릎·엉덩이가 탄력 있게 반응한다. 양방향을 단순 역재생하지 않고 각각 조정한다.
- 출발·정지와 머리·귀·꼬리의 늦게 따라오는 움직임을 연결한다. 현재 속도·이동량·클립 길이를 초안 기준으로 유지하며 본게임 수치로 확정하지 않는다.
- 이전 원본·동작·비교 자료는 BeforeElasticRevision에 보존한다. 이전 동작과 자세가 같아야 한다는 검사는 교체하고 외형 원본 보존·접지·공중 구간·가져오기·연결·수동 영역을 확인한다.
- 정상/느린 연결 재생, 전환 중 정지·재개·초기화와 네 방향·가까운/축소 구도를 실제 Game 창에서 확인한다. 결과는 **2-3 탄력 동작 사용자 확인 대기**로 남긴다. 신남·호기심은 그 이후다.

#### 2-4 첫 검증 장면

- **도구 운반:** 작은 나무 갈퀴를 두 발로 들고 이동 → 멈춰 내려놓기 → 네 발 자세로 바꾸기 → 손잡이를 입으로 물고 짧게 이동 → 내려놓고 두 발로 돌아와 다시 들기.
- **수레 소동:** 두 발로 끌기 → 자세를 바꾸다 놓치기 → 수레가 조금 굴러감 → 잠깐 바라보기 → 다가가 두 발로 다시 잡고 이어가기.

빈손 야외 이동 외에 작업·운반 중에도 네 발 전환을 허용하는 방향이다. 실제 경로 오류·물건 유실·영구 정체와 의도된 연출을 구분한다. 수레를 입이나 목·어깨의 끈으로 끄는 방식은 이번 첫 검증에 포함하지 않고 아이디어로 보존한다.

#### 2단계 확인 방법

- 캐릭터 가까이 보기와 마을 전체 보기에서 각각 외형·동작을 확인한다.
- 실제 Unity Game 창에서 자세 전환·소품 전달·수레 회수·카메라 조작을 확인한다.
- 좌우 360도 회전, 상하 회전, 높낮이·평면 이동과 확대/축소를 각각 및 조합해 확인한다. 기본 구도 복귀는 위치·회전·높이·확대 상태를 함께 되돌리는지 확인한다.
- 여러 방향과 높은·낮은 시점에서 주민·건물·소품이 자연스럽게 보이는지 확인한다. 합의한 조작 범위에서 지면 아래 진입·화면 뒤집힘이 없고, 화면 비율을 바꿔도 조작과 기본 구도 복귀가 동작하는지 확인한다.
- 종합 장면은 실제 시간으로 **5분 관찰**해 반복감과 행동 밀도를 확인한다. 본게임 장시간 안정성 검증과 구분한다.
- 작은 창과 가로·세로 비율에서 확인한다. 출시 최소 해상도와 성능 목표는 별도 합의한다.
- 구현·자동 검사·실제 관찰·사용자 확인을 따로 기록한다. 외형과 연출은 사용자 확인 없이 통과로 처리하지 않는다.

### 주요 검증 상황

- 무입력 상태에서 주민의 일·휴식·생활 순환과 회복이 이어지는가.
- 확장 제안을 무시해도 현재 영역에서 정상 생활과 가능한 질적 성장이 이어지는가.
- 식량·공간 부족이 영구 정체나 붕괴를 만들지 않는가.
- 장식과 건설 후보지가 겹치거나 통행이 어려워질 때 합의한 보존·복구 규칙을 지키는가.
- 계절·날씨 전환이 화면과 행동·생산에 반영되며 급격한 오류를 만들지 않는가.
- 이동·운반·건설 중 저장 후 복원할 때 중복 생산·예약 유실·진행 소실이 없는가.
- 보존 모드·일시정지·배속 전환이 합의한 생활·시간 규칙을 지키는가.
- 실제 창의 버튼·음량·크기 변경과 재실행 후 설정 유지가 정상인가.
- 실제 목표 환경의 장시간 관찰과 성능 측정이 합의 기준을 통과하는가.

## 9. 프로토타입 재사용 후보와 남은 검증

기존 코드는 **재사용 후보이며 본게임 규모에서 검증된 완성 기반이 아니다.**

| 후보 | 본게임에서 확인할 점 |
|---|---|
| 자율 생활·개인차 | 여러 종·직업·환경 반응과 본게임 규모에서 판단이 유지되는지 |
| 이동·충돌 회피·예약·실패 복구 | 변경되는 지형·건물·장식과 늘어난 주민에 대응하는지 |
| 작물→수확→운반→저장→소비 | 다종 자원과 계절 영향을 연결할 수 있는지 |
| 헛간 자율 건설 | 반복되는 건설·부지 선택·확장과 꾸미기 관계로 확장 가능한지 |
| 카메라·낮밤·식물·연기 | 기존 이동·확대 로직을 검토하되 좌우·상하 회전, 높낮이 이동, 기본 구도 복귀까지 확장 필요. 여러 시점·자유로운 창 비율에서 품질과 가독성 재검증 |
