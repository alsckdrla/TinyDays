# Tiny Days 본게임 작업 규칙

- PC 공통 거리별 키 속도(v0.137): WASD/화살표·Q/E는 현재 중심점 거리×0.5m/s, 최소 계산 거리1m를 사용한다.8m 이하 고정 속도는 키보드에 적용하지 않으며 기존 마우스 감도는 보존한다. Q/E도 패널 위에서 허용하고 텍스트 입력/설정/색상창/포커스 상실에서 차단한다. 농가 높이 오프셋과 추적 중심을 포함한다.

- PC 공통 키보드 카메라(v0.136): 생활·동작·외형·농가·집 검토에서 WASD/화살표는 카메라 기준 지면 평행 이동이다. 대각선 정규화·동일 키 중복 방지·실제 시간 기준·수직 구도 대응을 유지한다. 패널 위에서는 허용하고 입력창·설정/색상창·포커스 상실에서는 차단한다. 주민 따라보기는 이동 오프셋을 사용하며 Home으로 복구한다. 프로토타입은 제외한다.

- PC 공통 검토 카메라(v0.132): 생활·동작·외형·농가·집 검토는 왼쪽 드래그 회전·오른쪽 드래그 패닝이다. 농가 왼쪽 클릭 선택/더블클릭 따라보기와 기존 가운데 버튼·휠·Q/E·Home·감도는 유지한다. 다른 PC 재빌드에서 옛 좌패닝/우회전으로 되돌리지 않는다.

- 매 작업 전 [Docs/MasterPlan.md](Docs/MasterPlan.md) → [Docs/Progress.md](Docs/Progress.md) → 현재 단계 관찰 문서 순서로 읽고, 본게임의 확정 범위·미정 항목·현재 단계·통과 기준·남은 검증을 확인한다. 본게임은 마스터 플랜을 최우선 기획 기준으로 삼고, Progress 문서는 PC 간 작업 재개를 위한 최신 체크포인트로 사용한다.
- 새 사용자 지시가 기준을 변경하면 충돌을 알리고 합의한 변경을 마스터 플랜에 반영한 뒤 작업한다. 후보·예시·미정 내용을 임의로 확정하거나 구현하지 않는다.
- 요청을 이해한 대로 먼저 요약하고 승인 후 수정한다. 합의한 계획의 실행 요청은 별도의 “수정 실행하자”를 기다리지 않고 진행한다.
- 사용자가 요구하기 전에는 수정 디테일을 나열하지 않는다. 작업 후에는 **작업 / 확인 / 다음**으로 간결하게 보고하고 다음 작업의 권장 모델과 플랜 모드 여부를 안내한다. 실제 모델을 변경하지 않았다면 변경했다고 말하지 않는다.
- 작업 뒤 마스터 플랜의 진행·검증 상태를 갱신한다. 기획 변경은 변경 이력에도 남긴다. 구현·자동 검사·실제 플레이·사용자 확인을 구분하며 미검증이나 오류가 남으면 완료로 표시하지 않는다.
- 작업으로 구현·검증·합의·미완료 상태가 달라지면 `Docs/Progress.md`도 반드시 갱신한다. 최종 갱신일, 현재 단계, 완료 내용, 자동 검사·실제 입력·사용자 확인, 남은 문제와 다음 작업 순서를 최신 상태로 유지한다. 중단·실패도 다음 PC에서 이어갈 수 있도록 기록한다. 상태 변화 없는 단순 질의에는 중복 기록하지 않는다. 이 규칙은 모든 PC에 동일하게 적용하며, 업로드 시 진행 문서를 함께 포함하고 로컬 저장과 원격 동기화 여부를 구분해 보고한다.
- 계획을 제시할 때 첫 줄에 실행 권장 모델·추론 강도·모드를 명시한다.
- GitHub 업데이트 시 `Docs/References` 전체·코드·필요 자산·최신 MasterPlan/Progress와 변경된 루트/프로젝트 AGENTS.md를 함께 커밋하고 원격 커밋의 포함 여부를 확인한다. 현재 상황은 Progress, 작업 규칙은 AGENTS.md에 기록하며 규칙 변경도 함께 반영한다. Logs 실행 파일·캐시와 PC 전용 .lnk는 로컬에 보존한다.
- 다른 PC에서 성인 동작 검토 프로그램을 재개할 때도 현재 왼쪽 세로 검토 패널을 유지한다. MasterPlan의 ‘PC 공통 검토 UI’ 기준을 따르고, 이전 상단 가로 버튼 배치로 되돌리지 않는다. `Logs` 실행 파일은 Git 제외이므로 최신 소스를 받은 뒤 `Tools/RebuildAdultRabbitMotion.ps1 -SkipArt`로 해당 PC에서 재빌드하고 버튼 배치를 확인한다. Codex 앱 자체의 모드 선택 UI가 아니라 프로젝트 검토 프로그램의 UI에 관한 규칙이다.
- 본게임 단계와 프로토타입의 6단계는 별개다. 기존 프로토타입은 재사용 후보이고, 수치·규모·모델·배속·기술 선택을 본게임 확정 기준으로 승계하지 않는다.
- 재사용을 검토할 때는 ../TinyDaysPrototype/Docs/MasterPlan.md, PrototypePlan.md, Decisions.md, Progress.md 및 해당 프로젝트 AGENTS.md를 확인한다. 프로토타입 수정은 해당 범위의 사용자 요청 없이 수행하지 않는다.
- 시각 기준은 마스터 플랜과 `Docs/References/Tiny Days 참고이미지_01.png`를 따른다. 1.0은 저기술 농경세계이며 이미지의 현대 시설·대형 UI를 자동 채택하지 않는다.
- Unity 2022.3.20f1 / Blender 5.2.1을 유지한다. 기존 수동 자산·사용자 변경을 보존하고 원본 .blend·생성 스크립트·Unity 소스를 남긴다. 재사용하는 생성 도구의 덮어쓰기 범위를 먼저 확인한다.
- 성인 토끼 기본 원본은 `ArtSource/AdultRabbit - 01.blend`이며 생성 도구는 이 파일에 저장하지 않는다. 외형/36동작/출입/물 주기/벤치 파생 모델 반영은 `Tools/RebuildCanonicalRabbit.ps1`을 사용한다(아트 반영 후 검사/Windows 빌드만은 `-SkipArt`). 기존 액션을 보존하는 메시 반영과 애니메이션 재생성을 구분한다. 구형 `generate_adult_rabbit.py`는 명시적 `-- --legacy-restore`에서만 허용하며 신규 기본 모델로 사용하지 않는다. 옛 농가와 RabbitStudy/RabbitMotion은 비교용으로 보존한다.
- Blender 자동화를 사용할 때는 --background --factory-startup --python-exit-code 1을 사용하고 사용자 애드온·환경설정을 수정하지 않는다.
- 실제 게임 창 검증과 별도 테스트 창·직접 함수 호출을 구분한다. 프로토타입 16× 성능 미달과 추가 최적화 보류를 완료로 처리하거나 임의로 배속을 제한하지 않는다.
- 유료 자산 구매·외부 연결·업로드·원격 저장소 생성은 별도 사용자 요청 없이 하지 않는다. 문서와 이미지를 Git 관리 대상으로 유지하고 다른 PC로 이전할 때 최신 코드·문서·필요 자산의 실제 커밋·푸시 여부를 확인한다.

- v0.16 합의: 2-6 피드백 반영은 자유 카메라를 선행한다. 농가의 문·문틀·지붕 기본 품질을 보완하고, 캐릭터 기본 디자인을 확인한 뒤 핵심 애니메이션을 재개한다. 식물의 약한 바람 흔들림을 추가하며 바람 세기 변화·날씨 연동은 후속 합의 대상으로 둔다.
