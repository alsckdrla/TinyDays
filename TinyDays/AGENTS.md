# Tiny Days 본게임 작업 규칙

- 매 작업 전 [Docs/MasterPlan.md](Docs/MasterPlan.md)를 읽고 본게임의 확정 범위·미정 항목·현재 단계·통과 기준을 확인한다. 본게임은 이 문서를 최우선 기획 기준으로 삼는다.
- 새 사용자 지시가 기준을 변경하면 충돌을 알리고 합의한 변경을 마스터 플랜에 반영한 뒤 작업한다. 후보·예시·미정 내용을 임의로 확정하거나 구현하지 않는다.
- 요청을 이해한 대로 먼저 요약하고 승인 후 수정한다. 합의한 계획의 실행 요청은 별도의 “수정 실행하자”를 기다리지 않고 진행한다.
- 사용자가 요구하기 전에는 수정 디테일을 나열하지 않는다. 작업 후에는 **작업 / 확인 / 다음**으로 간결하게 보고하고 다음 작업의 권장 모델과 플랜 모드 여부를 안내한다. 실제 모델을 변경하지 않았다면 변경했다고 말하지 않는다.
- 작업 뒤 마스터 플랜의 진행·검증 상태를 갱신한다. 기획 변경은 변경 이력에도 남긴다. 구현·자동 검사·실제 플레이·사용자 확인을 구분하며 미검증이나 오류가 남으면 완료로 표시하지 않는다.
- 본게임 단계와 프로토타입의 6단계는 별개다. 기존 프로토타입은 재사용 후보이고, 수치·규모·모델·배속·기술 선택을 본게임 확정 기준으로 승계하지 않는다.
- 재사용을 검토할 때는 ../TinyDaysPrototype/Docs/MasterPlan.md, PrototypePlan.md, Decisions.md, Progress.md 및 해당 프로젝트 AGENTS.md를 확인한다. 프로토타입 수정은 해당 범위의 사용자 요청 없이 수행하지 않는다.
- 시각 기준은 마스터 플랜과 `Docs/References/Tiny Days 참고이미지_01.png`를 따른다. 1.0은 저기술 농경세계이며 이미지의 현대 시설·대형 UI를 자동 채택하지 않는다.
- Unity 2022.3.20f1 / Blender 5.2.1을 유지한다. 기존 수동 자산·사용자 변경을 보존하고 원본 .blend·생성 스크립트·Unity 소스를 남긴다. 재사용하는 생성 도구의 덮어쓰기 범위를 먼저 확인한다.
- Blender 자동화를 사용할 때는 --background --factory-startup --python-exit-code 1을 사용하고 사용자 애드온·환경설정을 수정하지 않는다.
- 실제 게임 창 검증과 별도 테스트 창·직접 함수 호출을 구분한다. 프로토타입 16× 성능 미달과 추가 최적화 보류를 완료로 처리하거나 임의로 배속을 제한하지 않는다.
- 유료 자산 구매·외부 연결·업로드·원격 저장소 생성은 별도 사용자 요청 없이 하지 않는다. 문서와 이미지를 Git 관리 대상으로 유지하고 다른 PC로 이전할 때 최신 코드·문서·필요 자산의 실제 커밋·푸시 여부를 확인한다.

- v0.15 합의: 캐릭터 디자인·애니메이션은 임시 사용하며 추가 제작·보완은 재개 합의까지 보류한다. 2-3~2-5를 완료로 처리하지 않고 2-6 농가·생활 장면을 선행한다. 농가 검증은 최종 캐릭터 품질 승인이나 3단계 자율 생활 완료가 아니다.
